# 虚拟银行使用与验收说明

## 功能与角色

学生和教师进入银行时按需创建一个余额为 `0.00` 的虚拟账户，可以查看余额、向启用用户转账并查询本人流水。银行管理员和超级管理员额外拥有账户检索、充值、冻结、解冻及全量流水查询权限；充值时填写目标用户名（学生账号即学号），由服务端解析实际用户 ID。所有身份与权限由应用服务器根据会话判断，客户端不连接 MySQL，也不能通过伪造用户 ID 操作他人账户。

## 页面

- 普通用户页签：账户首页、转账、流水明细；
- 管理员页签：账户管理、充值与冻结、全量流水；
- 消息中心的银行通知可直接打开“流水明细”；
- 所有 Socket 请求在后台线程执行，完成后回到 Swing 事件线程更新页面；请求期间按钮禁用。

## 资金规则

- 金额由 MySQL `DECIMAL(15,2)` 和 Java `BigDecimal` 保存，不使用浮点数；
- 转账和充值只接受大于零、最多两位小数、非科学计数法且不超过 `9999999999999.99` 的金额；
- 转账按账户 ID 固定顺序加锁，并在持锁后再次检查余额，两个并发请求不能造成透支；
- 每次转账或充值使用 UUID 业务编号，数据库唯一约束防止重试造成重复入账；
- 充值前必须确认目标用户存在且已启用，否则返回“目标用户不存在或已停用”，不创建账户、不写流水或通知；
- 流水只能新增，应用不提供修改或删除历史流水的接口；
- 冻结账户可以查看、收款和接收商店退款，但不能主动转账或支付；
- 余额变更、流水和通知在同一个 JDBC 事务中提交或回滚。

流水类型包括管理员充值 `ADMIN_TOPUP`、转账支出 `TRANSFER_OUT`、转账收入 `TRANSFER_IN`、商店支付 `SHOP_PAYMENT` 和商店退款 `SHOP_REFUND`。商店后续通过服务端的 `BankPaymentWriter` 复用同一数据库事务，不能从客户端补发第二次扣款请求。

## 消息中心联动

| 事件 | 接收人 | 类型 | 跳转 |
| --- | --- | --- | --- |
| 他人转账成功 | 收款人 | `BANK_TRANSFER_RECEIVED` | `BANK_LEDGER` |
| 管理员充值成功 | 目标用户 | `BANK_ACCOUNT_TOPPED_UP` | `BANK_LEDGER` |
| 账户实际冻结或解冻 | 目标用户 | `BANK_ACCOUNT_STATUS_CHANGED` | `BANK_LEDGER` |

用户主动操作不通知自己；同一充值或转账业务重试不会重复入账或重复通知，状态没有变化时也不重复通知。消息不包含密码、数据库凭据或其他敏感信息。

## 环境和数据库

服务端读取以下环境变量：

```powershell
$env:VCAMPUS_DB_URL = 'jdbc:mysql://127.0.0.1:3306/vcampus?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
$env:VCAMPUS_DB_USER = '你的数据库用户名'
$env:VCAMPUS_DB_PASSWORD = '你的数据库密码'
```

全新数据库依次执行 `database/schema.sql` 和 `database/seed.sql`。旧数据库先备份，再执行 `database/migrations/007_bank.sql`，最后执行最新 `database/seed.sql`。脚本不包含数据库密码或真实个人数据。

银行种子数据依赖匿名演示账号 `2026000001`、`2026000002` 和 `T0000001`。如果账号尚未创建，先通过超级管理员的账号管理创建，再重跑 `seed.sql`。固定种子业务编号和事务保证脚本重复执行不会使余额翻倍。

## 手工验收

1. 启动 MySQL 和应用服务器，再打开两个普通客户端与一个银行管理员客户端；
2. 普通用户首次进入银行，确认自动开户且只能看到三个普通页签；
3. 管理员用用户 A 的用户名（学生账号即学号）充值，确认余额、充值流水和消息同时出现；再输入不存在或已停用的账号，确认显示可读提示且没有任何资金数据写入；
4. 用户 A 向用户 B 转账，确认两边余额与成对流水正确，B 收到通知且 A 不收到自通知；
5. 重复提交同一个业务编号，确认余额和流水不重复变化；
6. 冻结 A，确认 A 不能转账，但仍能接收 B 的转账；解冻后恢复转账；
7. 普通用户尝试调用管理员动作应被服务端拒绝；
8. 管理员在“全量流水”留空用户 ID 查看全部流水，填写用户 ID 时只查看该用户；
9. 从三类银行通知详情进入页面，确认直接选中“流水明细”；
10. 连续执行两次 `seed.sql`，确认三个演示账户的种子余额不增加第二次。

本任务不替用户启动服务端或改动本机 MySQL。MySQL 多客户端场景需在用户按上述步骤启动环境后人工联调。
