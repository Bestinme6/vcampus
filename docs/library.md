# 虚拟图书馆使用与验收说明

## 功能和角色

学生与教师可以检索馆藏、查看本人借阅、借阅、归还和续借。图书管理员可以维护书目及实体馆藏、代办借还、登记遗失并查询所有借阅记录。超级管理员只进入管理页，不能以读者身份借书。所有权限均由服务端再次校验。

## 借阅规则

| 身份 | 同时借阅上限 | 初始借期 | 唯一一次续借 |
| --- | ---: | ---: | ---: |
| 学生 | 5 本 | 30 天 | 15 天 |
| 教师 | 10 本 | 60 天 | 30 天 |

存在任何逾期记录时禁止新增借阅和续借，但仍允许查看与归还。续借从原应还时间延长，服务器回执中的时间是最终依据。

## 读者操作流程

1. 登录后从工作台打开“图书借阅”。
2. 在“图书检索”按书名、作者、ISBN 或分类查询，选择有可借馆藏的书目。
3. 确认借期和预计到期日后提交；成功后以服务器回执为准。
4. 在“我的借阅”切换当前、即将到期、逾期和历史范围。
5. 仅当记录显示“可续借”时执行续借；归还前需再次确认。

## 管理员操作流程

- “书目馆藏”：新建或编辑书目、启停书目、增加实体馆藏、修改馆藏状态。
- `LOST`、`DAMAGED`、`WITHDRAWN` 必须填写原因；借出中的 `ON_LOAN` 馆藏不能手工改状态。
- “借还办理”：先输入用户名、馆藏条码和业务类型进行校验，确认借阅人、额度、逾期和馆藏状态后才能提交。
- “借阅查询”：按用户、姓名、书名或条码搜索，并可筛选活动状态和逾期状态。

## 馆藏状态

| 状态 | 含义 |
| --- | --- |
| `AVAILABLE` | 可借阅 |
| `ON_LOAN` | 已借出，由借还事务维护 |
| `LOST` | 遗失并关闭借阅 |
| `DAMAGED` | 损坏，暂停流通 |
| `WITHDRAWN` | 下架，不再流通 |

## 借阅生命周期通知

借阅、续借、正常归还和登记遗失成功后，借阅人分别收到 `LIBRARY_BORROWED`、`LIBRARY_RENEWED`、`LIBRARY_RETURNED` 和 `LIBRARY_LOST`。自助操作与管理员代办均发送，内容包含书名、馆藏条码及对应的应还时间、归还时间或遗失原因。这些回执与业务状态在同一个数据库事务中提交或回滚。

服务启动时立即扫描一次，之后每小时扫描。应还时间处于未来 3 天内时发送 `LIBRARY_DUE_SOON`；超过应还时间时发送 `LIBRARY_OVERDUE`。通知写入与对应发送标记位于同一数据库事务中，同一笔借阅不会重复发送同类提醒。续借会清除到期提醒标记，以便按照新的应还时间重新提醒。全部六类图书馆消息都可从详情打开“我的借阅”。

## 环境与数据库初始化

- Java 21、MySQL Server 8.0.44、Maven 3.9 或 Eclipse Maven 支持。
- 服务端通过 `VCAMPUS_DB_URL`、`VCAMPUS_DB_USER`、`VCAMPUS_DB_PASSWORD` 获取数据库配置。
- 新数据库依次执行 `database/schema.sql`、`database/seed.sql`。
- 已有数据库依次应用 `database/migrations/001_auth_columns.sql`、`002_notifications.sql`、`003_library.sql`、`004_library_receipt_notifications.sql`，再执行 `database/seed.sql`。
- 脚本不包含密码。先用超级管理员账号管理创建匿名账号 `2026000001`、`2026000002` 和 `T0000001`，然后重新执行 `seed.sql`，即可生成四类借阅演示记录。

## 课程演示顺序

1. 学生检索并借阅一本可借图书，随后在“我的借阅”查看回执。
2. 学生续借一次，再次续借应被拒绝。
3. 使用逾期学生账号尝试借阅，确认被阻止但仍可归还。
4. 图书管理员新建书目和馆藏，修改损坏状态并填写原因。
5. 管理员通过两阶段校验替学生借书，再正常归还。
6. 管理员将一本借出馆藏登记为遗失并填写原因。
7. 在借阅查询中验证用户、活动状态和逾期筛选。
8. 等待或手工触发通知扫描，验证到期与逾期消息仅生成一次。
9. 从消息中心打开通知，确认直接进入“我的借阅”。
10. 两个客户端同时借阅最后一本可借馆藏，确认恰好一个成功。

## 并发行为

借阅事务先锁定借阅人及候选馆藏，并使用活动借阅唯一键作为数据库最终防线。两个客户端争抢最后一本馆藏时，只允许一个事务创建活动借阅；另一个客户端收到“该馆藏刚刚被其他用户借出”等可读提示。

## 故障恢复

- 客户端断线或服务端未启动：界面提示连接失败；保留原有表格数据，确认服务端端口后重试。
- 数据库不可用：服务端返回“图书馆数据暂时不可用，请稍后重试”；恢复 MySQL 后无需重启客户端即可再次查询。
- 借阅冲突：刷新馆藏或借阅记录，依据服务器最新状态继续操作。
- 通知扫描失败：本轮事务回滚且不写标记；数据库恢复后下一个小时扫描会再次尝试。
- 迁移约束名称不匹配：先核对数据库是否已应用前序迁移，不要直接删除业务表。
