# VCampus 演示指南

本指南面向课程答辩和交付验收，推荐用 15～20 分钟展示“管理员配置 → 业务操作 → 用户看到结果与通知”的完整闭环。

## 1. 演示角色与账号

演示前通过系统界面准备账号，密码单独安全保存，不写入仓库：

| 账号类型 | 建议数量 | 用途 |
| --- | ---: | --- |
| 超级管理员 | 1 | 账户创建、角色分配、系统级演示 |
| 教师/业务管理员 | 1～2 | 教务、图书、商店、银行、论坛管理 |
| 学生 A | 1 | 主业务流程和消息接收 |
| 学生 B | 1 | 收件人隔离、库存/名额竞争等对照场景 |

超级管理员只用于系统级操作。日常业务管理尽量切换到具备相应业务角色的教师或管理员账号，以便展示权限边界。

## 2. 演示前检查

- [ ] 服务端与客户端来自同一提交，旧进程已关闭
- [ ] 已执行 `mvn clean verify`
- [ ] 已备份演示数据库和附件目录
- [ ] MySQL、服务端端口与文件目录配置正确
- [ ] JavaFX 运行时检查通过
- [ ] 所有演示账号可登录，角色和密码状态符合预期
- [ ] 学生档案、课程、图书、商品和账户余额足以完成演示
- [ ] 准备两台客户端或可快速切换的两个客户端进程
- [ ] 屏幕上没有数据库密码、终端敏感变量或真实个人数据
- [ ] 完整彩排一次，并记录数据库备份恢复点

基础数据优先通过系统管理页面准备。服务端会自动处理当前 schema/seed，不需要在演示现场逐个执行历史迁移。

## 3. 推荐演示流程

### 3.1 登录与角色工作台（2 分钟）

1. 使用学生账号登录，展示默认 JavaFX 门户、角色可见菜单和未读消息角标。
2. 使用超级管理员登录，展示不同角色对应的工作台和权限差异。
3. 说明客户端通过 Socket 访问服务端，不能直接连接 MySQL。

### 3.2 账户与学生管理（2 分钟）

1. 超级管理员查询或创建一个演示账号，分配角色并展示启停能力。
2. 打开学生档案，展示基础信息、院系专业和状态维护。
3. 用普通学生账号验证不能执行管理员操作。

### 3.3 教务闭环（3 分钟）

1. 教务管理员展示学期、课程、教学班与排课信息。
2. 学生完成选课或退课，并查看个人课表。
3. 教师录入或提交成绩，学生端查看结果。

### 3.4 图书馆闭环（2 分钟）

1. 学生检索图书并发起借阅或预约。
2. 图书管理员完成借出、归还或预约处理。
3. 学生打开消息中心确认业务通知。

### 3.5 银行与商店闭环（3 分钟）

1. 展示学生账户余额和流水。
2. 学生在商店下单，确认余额、库存和订单状态同步变化。
3. 管理员处理订单或调整账户，回到学生端核对结果。

### 3.6 论坛与消息中心（3 分钟）

1. 学生发帖或互动，论坛管理员展示审核与管理权限。
2. 管理员向指定用户或角色发布消息。
3. 学生确认未读角标变化，执行读取、重新标未读、再次读取和删除。
4. 切换学生 B，证明定向消息不会泄露给其他收件人。

### 3.7 收尾（1 分钟）

展示服务端日志和数据库持久化结果，概括三层架构、统一协议、权限校验与自动化测试基线。不要在投屏中展示密码或完整数据库连接串。

## 4. 演示故障恢复

| 现象 | 快速处理 |
| --- | --- |
| 客户端连接失败 | 确认服务端已启动、主机端口一致，并检查是否有旧服务端占用端口 |
| 数据库不可用 | 停止演示写操作，检查 MySQL 与环境变量；必要时恢复演示前备份 |
| 页面状态未刷新 | 先使用页面刷新/重新查询；仍异常时重启同一版本的客户端与服务端 |
| 账号无法登录 | 用超级管理员检查账号状态、角色和首次改密状态，不现场修改数据库 |
| 余额、库存或名额不足 | 使用对应管理页面补充演示数据，不绕过服务端直接改表 |
| 图片或试卷无法打开 | 检查附件目录权限及备份是否与数据库来自同一时点 |
| 消息角标不一致 | 刷新消息列表并核对当前登录账号；保留日志时间点供复盘 |

## 5. 演示纪律

- 不使用真实个人数据。
- 不把密码、令牌和数据库导出纳入演示包。
- 不在现场临时执行未验证的迁移脚本。
- 不用 Swing 兼容入口代替默认 JavaFX 主流程；只有在被问到兼容性时再展示 `-Swing`。
- 出现异常时优先恢复到演示前备份，不在投屏状态下做不可逆数据修复。
