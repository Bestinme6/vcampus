# 校园论坛

## 入口与界面

默认 JavaFX 客户端在“工作台 → 校园论坛”打开原生 JavaFX + CSS 页面，不再嵌入旧 Swing 论坛。消息中心的论坛消息也打开同一原生详情页。其他业务模块继续使用现有 Swing 兼容界面；`--swing` 入口保留旧论坛，不提供此次全部新交互。

新版采用浅蓝白色卡片、深色正文、黑色按钮文字。可用内容区达到 1080px 时展示右侧公告和今日热榜；小窗口收起右栏，仍可通过“校园公告”查看公告。首页、详情、发帖和内容管理均连接真实 Socket 接口，没有生产环境演示数据开关。

## 用户功能

- 按板块、标题/正文/作者关键词检索；最新、热门、精华排序，每页 20 条。
- 发布帖子：标题 4—160 字，正文 1—10000 字。失败保留草稿，离开未发布的编辑器需要确认。
- 正文阅读、评论、回复评论；评论按页显示。锁定帖子仍可阅读，但不能新增评论或回复。
- 点赞和收藏以明确的开启/取消状态提交，重复请求不重复计数；每个用户每篇帖子最多一条对应记录。
- “我的帖子”可查看本人的正常、隐藏和删除状态；“我的收藏”只展示当前可访问的收藏。隐藏/删除内容不进入日常详情。
- 点赞、收藏不发送消息，避免通知过多；评论及成功且实际改变状态的管理操作继续联动消息中心。

### 评论删除和管理员隐藏的区别

| 操作 | 谁能执行 | 日常阅读 | 管理记录 | 能否恢复 |
| --- | --- | --- | --- | --- |
| 删除自己的正常评论 | 评论作者，包括管理员自己的评论 | 所有人都看不到 | 保留“已删除”记录 | 不能 |
| 隐藏别人的正常评论 | 论坛管理员、超级管理员 | 所有人都看不到 | 保留“已隐藏”记录和原因 | 可以 |
| 恢复隐藏评论 | 论坛管理员、超级管理员 | 父帖正常且板块启用时重新可见 | 留审核日志 | 不适用于作者已删除的评论 |

管理员处理他人评论应在“内容管理 → 内容审核 → 评论”中选择“隐藏”，不是冒充作者删除。新 JavaFX 和旧 Swing 的阅读列表使用相同规则。

### 回复与消息

普通评论通知楼主；回复评论还通知被回复的评论作者。同一人同时是楼主和被回复者时只收到一条回复通知；操作者不收到自己的评论通知。通知与评论在同一数据库事务中保存，失败一起回滚。

原评论后来被隐藏或删除时，已有回复显示“原评论已不可见”，不展示原评论内容或作者。跨帖回复、回复隐藏/删除评论均被拒绝。消息跳转目前定位帖子，不定位到某一条评论；帖子已不可访问时显示提示。

## 管理功能

只有论坛管理员和超级管理员拥有内容管理入口；服务端每次请求再次校验会话角色。

- 内容审核：隐藏/恢复、帖子锁定/解锁、置顶/取消置顶、精华/取消精华、设为公告/取消公告。
- 新 JavaFX 管理操作填写 2—255 字原因。重复设置不会重复写审核消息。
- 公告是独立标记，不是把置顶帖自动当成公告；被隐藏的公告不展示，恢复后沿用原公告标记。
- 板块管理：代码是内部标识，已有板块代码不可编辑；排序数字越小越靠前；新增板块保存后需启用。
- 审核日志只读并支持翻页；已删除记录保留供追溯，不能恢复。

### 热度口径

“热门”使用当前有效点赞数 + 正常评论数 × 2；首页置顶帖优先。相同分数按创建时间、帖子编号稳定排序。

“今日热榜”仅统计北京时间当天新增且仍有效的点赞、正常评论，按同一权重计算，最多 5 条，零互动不入榜。它不是全量点赞数排名，也不是定时推送；进入/刷新首页时重新读取。学校当天的起止时间由服务端以 `Asia/Shanghai` 计算后绑定到 SQL。

## 本次升级怎么运行

1. 关闭旧服务端和客户端，先备份已有数据库。
2. 在 MySQL Workbench 中打开项目**最新**的 `database/schema.sql`，执行整个文件。
3. 再打开并执行**最新**的 `database/seed.sql`。不要另外重跑旧论坛通知迁移，否则可能重新缩小消息类型约束。
4. 构建项目：`mvn clean verify`。Eclipse 用户先执行 Maven → Update Project，并确认使用 Java 21。
5. 启动 `com.vcampus.server.ServerMain`，再启动 `com.vcampus.client.ClientMain`；进入“工作台 → 校园论坛”。

本次论坛升级已合入 schema：新增点赞/收藏表、评论回复关联和公告字段，扩展 `FORUM_COMMENT_REPLIED` 通知约束；旧表新增字段/外键/索引先查询 `information_schema`，避免重复添加。新增论坛结构不清空已有帖子、评论或互动；seed 不填充虚假的点赞数或清空互动。

新版服务端与客户端需一起更新。新接口携带 `forumVersion=2`，若服务端过旧，客户端会明确提示版本不兼容，而不是显示假零。此版本无需使用 Figma，也不受 Figma 额度影响。

## 验证范围与本机验收

自动化包括：真实 MessageCodec 临时 Socket 请求、会话权限、H2 事务与通知回滚、并发重复点赞、查询隔离、回复去重、北京时间边界、UI 线程/过期回调、消息桥接、输入校验和小窗口布局。schema 静态检查仅验证脚本结构，**不等同于执行过 MySQL 升级**。

`ForumVisualTest` 在 `vcampus-client/target/forum-screenshots/` 生成实际 JavaFX 场景截图。包含 1220/1060/780px 内容宽度的首页、详情评论、编辑器、管理页、空列表、加载和错误状态；这些截图使用测试夹具数据，不代表真实库中已有这些帖子。`mvn clean` 会清理并重新生成这些图片。

2026-08-31 验证记录：根目录 `clean verify` 共 399 项测试（common 56、server 196、client 147），失败/错误/跳过均为 0。视觉检查修复了小窗口顶部按钮文字省略、管理表格过小及底部分页无法滚动到达的问题。

另在独立测试 JVM 中传入 `-Dforum.visual.scale=1.25`，以 JavaFX SnapshotParameters 对场景做 125% 渲染，输出到 `target/forum-screenshots-125/`；已检查首页、评论区、管理底部和加载页。**这是场景渲染缩放，不是真实 Windows 系统 DPI 验收**，未更改用户显示设置。

本轮未启动正式服务端、未连接或修改用户 MySQL。以下需要在本机升级后验收：

- 用 A、B 两个客户端登录；A 发帖，B 点赞、收藏、评论，确认 A 的消息跳转到原生详情。
- A 回复 B 的评论，B 收到回复通知；自己回复自己不产生给自己的消息。
- 管理员隐藏 B 的评论，两端日常列表刷新后均消失；管理员在管理页恢复后重新可见。
- B 删除自己的评论，管理员只能在管理页看到“已删除”，不能恢复。
- 设置公告，检查公告栏和作者管理通知；隐藏公告后公告栏不展示。
- 旧库执行 schema 两遍、seed 两遍，核对无重复列/索引错误，既有业务记录和互动保留。请在备份或隔离库上先验证。
- 根据实际 Windows 显示缩放再检查最小窗口、弹窗、长内容和键盘操作；自动化缩放检查不能替代真人验收。
