# 系统配置与审计查询

系统管理用于维护会直接影响教学业务展示的少量全局配置，并提供统一审计日志的只读查询。它不是服务器运维控制台，不读取或修改数据库密码、Socket 端口、线程数、附件目录等部署参数。

## 权限边界

- 只有基础身份为 `SUPER_ADMIN` 的账号可以看到入口并调用四个 `system.` 请求。
- 学生、教师以及附加了全部业务管理员角色的教师都无权访问。
- 客户端隐藏入口只是界面约束；服务端会对加载、保存和查询逐次验证会话与精确角色集合。
- 审计日志只能查询，不能在客户端修改或删除。

## 基础配置

“基础配置”页包含两组设置：

- 学期设置：选择已有学期，编辑学期名称、开始/结束日期、选课开始/结束时间、退课截止时间与学期状态。这里不创建或删除学期，也不修改学年和学期序号。
- 节次时间：一次提交每日第 1—12 节的开始与结束时间。某一节可以整行留空；填写时两个时间必须同时存在、开始早于结束，而且相邻已配置节次不能重叠。

节次保存为单个事务：12 行要么全部生效，要么全部回滚。配置后的钟点由学生课表、教师课表和“我的校园”本周课程共同使用；未配置钟点时只显示节次，不编造时间。

## 审计查询

“审计日志”页按时间倒序分页展示，每页 20 条，可组合使用以下条件：

- 用户名或姓名关键词；
- 动作代码前缀，例如 `system.config.`；
- 结果代码；
- 开始日期和结束日期，按校园时区 `Asia/Shanghai` 的自然日边界查询。

表格显示时间、用户、动作、结果和客户端地址。用户后来被删除或无法关联时，历史记录仍可按其保留字段展示。

统一审计页读取 `audit_logs`，当前覆盖登录、账户管理、图书流通、图书馆论文维护以及系统配置变更。银行交易、商店库存、论坛审核各自有更完整的领域流水或管理日志，不混入本页；因此本页不是所有业务历史的总账。

## 协议与数据

系统管理沿用三层架构：JavaFX 客户端通过 `MessageCodec` 请求 Socket 服务端，由服务层执行权限与输入校验，再通过 JDBC 访问 MySQL。相关动作是：

- `system.config.get`
- `system.config.updateTerm`
- `system.config.updatePeriods`
- `system.audit.search`

学期继续存储在 `academic_terms`。每日作息存储在 `class_period_times`，当前 schema 与 `018_system_management.sql` 都会幂等准备第 1—12 节空行；更新人和更新时间随保存写入。每次系统配置保存都会以 `SUCCESS`、`INVALID`、`NOT_FOUND` 或 `DATABASE_ERROR` 结果写入统一审计。

## 验收要点

1. 超级管理员能加载和保存已有学期，非法日期顺序被拒绝。
2. 12 节作息能整体保存；缺行、单边时间、逆序或重叠被拒绝且不会部分写入。
3. 学生与教师刷新课表后看到统一钟点，空配置仍正常显示节次。
4. 审计筛选、日期边界、稳定排序和翻页结果正确，页面不存在编辑或删除入口。
5. 普通用户和业务管理员即使直接构造 Socket 请求也会收到“没有系统管理权限”。
