# 数据库自动准备验证记录

更新日期：2026-09-08。

## 当前行为

- `ServerMain` 在创建 Socket 服务之前准备数据库，`AdminBootstrapMain` 使用相同入口。
- `schema.sql` 和 `seed.sql` 从服务端构建产物加载，忽略其中的建库和 `USE`，始终使用经过校验的 JDBC 目标库。
- 首次空库会建表并导入基础数据；指纹变化或缺表时会在现有库上重新执行幂等建表、兼容升级和种子语句。
- 自动准备不再删除 VCampus 业务表，因此已有管理员、用户、课程、成绩、帖子、订单和流水会保留。
- 完整执行成功后才写入新指纹；执行失败时删除成功标记并停止服务端，下一次启动会重试。
- MySQL 命名锁串行化并发初始化；系统库和含糊的 JDBC 目标仍会被拒绝。
- `AdminBootstrapMain` 只负责创建首个超级管理员；同名且启用的超级管理员已存在时直接提示并正常退出。

## 自动化覆盖

- SQL 解析、资源打包、跨平台指纹和目标库校验。
- 相同指纹且表完整时跳过数据库写入。
- 指纹变化和缺表时应用脚本，并验证已有用户仍然存在。
- 种子执行失败后不保留成功标记，已有用户不被删除，修复后可重试。
- 外部表对 VCampus 表的引用在保留式升级后继续有效。
- 两个并发启动只有一个进程应用脚本。
- 只读账号可启动当前版本；需要结构升级时会失败并保留现有数据。

普通 `mvn clean verify` 不连接 MySQL。真实 MySQL 集成测试只允许在能创建随机 `vcampus_test_` 数据库的专用测试账号上启用；日常应用账号无需建库、删库、创建用户或授权权限。

## 使用边界

完整 `schema.sql` 必须使用 `CREATE TABLE IF NOT EXISTS` 或带存在性检查的兼容升级语句，`seed.sql` 必须保持幂等。MySQL DDL 不能整体回滚，结构升级前仍应备份。初始化失败时应用不会继续启动，也不会通过删除现有表来恢复。
