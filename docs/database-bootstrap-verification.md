# 数据库自动重建验证记录

日期：2026-09-07。采用用户批准的课程演示重建模式；旧业务数据不要求保留。

## 实现结果

- ServerMain 在创建 Socket 服务之前完成数据库准备；AdminBootstrapMain 也使用相同入口。
- schema/seed 从规范 database 目录打包到服务端 JAR。忽略脚本中的建库和 USE，始终在经过校验的 JDBC 目标库执行。
- 规范化 CRLF/LF 后计算 SHA-256；同指纹跳过重建，缺少版本记录、指纹失配或缺表则重建。
- 命名锁串行化并发初始化；先删除成功标记，最后在完整建表、播种和基本校验成功后重新记录。
- 拒绝系统库、含糊目标和外部表引用，不删除整个数据库或未知表。
- 现有商品图生成列的 VIRTUAL 修复与对应 H2 测试适配一并保留，完整 SQL 已通过真实 MySQL。

## 验证环境与结果

Java 21，Maven 3.9.11，MySQL 8.0.44。

使用单独初始化的临时 MySQL 实例，仅监听本机测试端口。没有在日常使用的 vcampus 数据库运行清空测试，也没有扩大其账号权限。

根目录 `mvn clean verify` 成功，实际使用项目内 Maven 和 settings 文件，并启用真实 MySQL 测试：

| client | 316 | 0 | 0 | 1 |

新增的 5 项脚本单元测试与 6 项 MySQL 集成测试全部执行通过：

- 引号、注释、字符串中的分号和动态 PREPARE 语句解析。
- 拒绝不完整 SQL、DELIMITER 和可执行注释。
- 完整资源打包、受控表清单、跨平台指纹与目标库校验。
- 旧表重建、未知表保留、第二次启动不清空账号。
- 指纹失配及缺表触发重建。
- 播种中途失败无成功标记、锁释放、后续重试成功。
- 外部表引用时拒绝破坏性操作。
- 两个并发启动只有一个重建。
- 只读账号可使用已匹配版本；版本失配时因权限不足而失败，已有表保持完整。

另以最终 JAR 从非项目根目录运行实际入口完成冒烟检查：

1. AdminBootstrapMain 自动准备临时库并以随机临时密码创建管理员。
2. ServerMain 启动后使用 MessageCodec 经真实 Socket 执行 auth.login，成功。
3. 关闭该测试服务端并再次启动，以同一账号登录仍成功。
4. 将目标指向系统数据库，进程以非零状态退出，未启动 Socket 服务。

密码和会话 token 未输出到检查记录。构建产物含 `database/schema.sql`、`database/seed.sql`。

## 使用边界

本功能不保留旧业务数据，不提供默认登录密码，不安装 MySQL，也不创建 MySQL 数据库或数据库账号。首次重建后运行管理员初始化工具创建新管理员。MySQL DDL 不具备整体回滚保证；应用不在重建失败时继续运行。

上述验证覆盖自动初始化与实际启动登录，不代表已完成各业务模块的所有多客户端人工验收。
