# VCampus 需求基线

## 1. 项目概况

- 项目名称：基于 C/S 的虚拟校园系统（VCampus）；
- 项目性质：课程作业；
- 计划交付日期：2026 年 9 月 20 日；
- 界面语言：简体中文；
- 数据库：MySQL Server 8.0.44；
- 基础身份：学生、教师、超级管理员，且每个账号只能拥有其中一种；
- 学生或教师可以在基础身份上附加符合规则的业务管理员角色；
- 在线课堂不在本次交付范围内。

## 2. 技术约束

- Java 21、Maven 多模块工程；
- JavaFX + CSS 默认桌面客户端；Swing 客户端作为独立兼容入口保留，不参与默认业务路由；
- Java Socket、多线程和输入输出流；
- MySQL 8.0.44；
- 三层 C/S：数据库 -> 应用服务器 -> 客户端；
- 客户端不得直接连接数据库；
- 网络和数据库操作不得阻塞 JavaFX 应用线程或 Swing 事件分发线程；
- 客户端与服务端使用 `MessageCodec` 二进制协议，不使用 Java 原生对象序列化；
- 数据库凭据通过环境变量提供，不写入源代码。

## 4. 角色与权限基线

| 角色 | 主要权限 |
| --- | --- |
| 学生 | 查询本人学籍；选退课、查课表与成绩；借还图书；购物；使用虚拟银行；使用论坛 |
| 教师 | 查看和维护本人教师联系方式；查询授课信息与学生名单；录入并发布本人教学班成绩；使用图书馆、商店、银行和论坛 |
| 超级管理员 | 独立基础身份；账号、角色和系统配置管理；访问六个业务管理模块 |
| 学籍管理员 | 修改、查询学生档案和学籍状态；账号及档案创建统一由超级管理员完成 |
| 教务管理员 | 课程、教学班、选课和成绩管理 |
| 图书管理员 | 图书、馆藏、借阅和归还管理；赔偿定价、费用政策、账单减免和退款 |
| 商店管理员 | 商品、库存和订单管理 |
| 银行管理员 | 虚拟账户、充值、冻结和流水查询；不得修改历史流水 |
| 论坛管理员 | 板块管理、帖子审核和违规内容处理 |

服务端必须在每次业务请求中校验会话和权限，不能只依赖客户端隐藏按钮。

角色组合还必须遵守以下规则：

- 学生和教师身份互斥，超级管理员不能再叠加其他角色；
- 学生只能附加图书管理员、论坛管理员；
- 教师可以附加学籍、教务、图书、商店、银行、论坛管理员中的任意组合；
- 教务、学籍、商店和银行管理员必须以教师为基础身份；
- 即使教师拥有全部六种业务管理员角色，也不具备超级管理员专属的账号和系统配置权限。

## 5. 默认业务约定

这些约定用于保证开发可以继续推进，后续可按课程要求调整：

- 学号：10 位数字字符串，例如 `2026000001`；
- 教工号：字母 `T` 加 7 位数字，例如 `T0000001`；
- 课程号：字母 `C` 加 6 位数字，例如 `C000001`；
- 书目编号：字母 `BK` 加 9 位数字，由服务端自动生成；
- ISBN：标准出版物可填写合法 ISBN-10 或 ISBN-13，校内资料允许留空；
- 图书条码：字母 `B` 加 9 位数字，由服务端并发安全地自动生成；
- 登录名默认使用学号或教工号，管理员使用独立账号；
- 初始密码必须在首次登录后修改；密码只以带盐哈希形式保存；
- 日常自助修改密码成功后立即退出当前会话，用户必须使用新密码重新登录；
- 金额使用 `DECIMAL` 或 Java `BigDecimal`，不得使用浮点数；
- 银行、商店库存和订单变更必须使用数据库事务；
- 图书费用默认宽限 1 天，从逾期第 2 天起每天 0.50 元，单笔逾期费上限 20.00 元；轻微破损、严重破损、遗失分别按赔偿参考价的 20%、50%、100% 计费；
- 图书账单与借阅关闭、馆藏状态和通知同事务；缴费/退款与银行余额、流水和通知同事务；
- 论坛助力的扣款、`FORUM_BOOST` 流水、助力记录和银行来源通知必须在同一事务中提交或回滚；客户端只能提交帖子、固定档位和 UUID；
- 业务记录默认采用逻辑状态变更，关键流水与审计日志不得物理删除。

## 6. 非功能要求

- 演示环境下支持多个客户端同时连接；
- 常规请求应给出加载、成功或错误反馈；
- 数据访问使用参数化 SQL，防止 SQL 注入；
- 客户端断线、错误输入和数据库不可用时应有可读提示；
- 关键操作记录统一审计摘要；银行、商店、教务和论坛领域流水继续保存详细业务事实，普通读取与高频个人状态不制造审计噪声；
- 主要协议、权限和服务行为应有自动化测试。

## 7. 界面基线

参考用户提供的工作台和课表图片，桌面客户端采用：

- 全局白色背景、浅色卡片和深色正文，保证表格与按钮文字清晰；
- 蓝色作为主要强调色，浅蓝色作为选中和提示颜色；
- 默认登录后进入“我的校园”，左侧“工作台”以模块宫格展示可访问功能；Swing 兼容客户端保持独立入口；
- 登录页采用第一组布局，校园主页采用第二组布局；统一浅蓝、白色、深色正文，登录配图为东南大学大礼堂建筑插画；
- 我的校园按真实学期起止日期、周次及星期筛选课程，用课程节次显示时间；未配置每日作息钟点时不得编造时刻；
- 概览仅查询本人数据；超级管理员显示管理入口；未开户显示“未开户”，请求失败显示“不可用”，不得用假零代替失败；
- 登录后的主窗口采用单窗口内容区；业务模块在工作台右侧切换，成功、失败、确认和短表单继续使用模态对话框；
- 所有已登录角色都可从左侧“退出登录”上方进入“账号安全”；页面同时展示账号概览、修改密码表单和本人最近 5 条登录、退出及修改密码活动；
- 学籍、账号管理、系统管理、教师信息、教务、消息中心、图书馆、论坛、商店和银行使用原生 JavaFX + CSS；工作台入口与消息中心业务深链复用对应模块实例；
- 消息中心宽屏使用消息列表与常驻详情左右分栏，内容区不足 980px 时改为上下布局；仅在用户点击消息后标记已读，选中卡片保持深色文字，较晚完成的旧请求不得覆盖当前筛选结果；
- 已读消息可重新标为未读并清空 `read_at`；服务端按会话校验消息所有权，成功后立即刷新列表和未读角标，在“仅已读”筛选中从当前结果移除；
- 用户只能软删除自己的单条消息；删除前二次确认，删除后检索、详情、未读统计和全部已读均忽略该记录，并立即刷新列表与角标；
- 首次发布教学班课表只通知任课教师；后续仅在时段实际改变时通知任课教师和在选学生，原样重新发布和已退课学生不产生消息；排课状态与通知保持同一事务；
- 教务使用“全校课程—培养方案课程—教学班”三层模型；课程只创建一次，必修/选修及建议学期属于具体培养方案，学生在匹配的课程下选择具体教学班；
- 学生“选课中心”展示符合培养方案的全部可选课程并负责首次选课；“我的课程”只展示当前已选课程并负责退课和同课程换班，两个入口不得复用同一页面；
- 教务与银行业务模块使用顶部两级页签：一级切换角色业务板块，二级只显示板块内功能；教师“任课班级”和“成绩管理”合并为“授课与成绩”，旧入口兼容跳转到合并页面；
- 培养方案按专业、连续入学年份和版本管理，发布后不可直接修改；排课先保存草稿，经教师与教室冲突校验后发布，学生和教师只看到发布版本；
- 图书馆书目检索支持按书目编号、书名、分类和历史借阅次数升降序排列；学生可在书目存在 `ON_LOAN` 馆藏时预约归还提醒，`LOST`、`DAMAGED`、`WITHDRAWN` 不计入预约条件；
- 图书馆使用原生 JavaFX 提供论文查询：按标题、作者、关键词和年份检索已上架论文，也可按规范化关键词分类筛选；查看摘要、出处、DOI、来源与分享说明，下载校内收录 PDF；无匹配结果时可由用户主动打开 Google Scholar 或 arXiv 检索；
- 图书管理员可以仅凭标题和作者保存未上架论文草稿并稍后补充来源，编辑论文（每篇最多 12 个关键词）、分块上传或替换 PDF、上架或下架；新建后清除旧筛选并定位到新记录；上传 PDF 时必须填写来源与分享说明；PDF 默认最大 30 MiB，服务端校验格式、完整大小和 SHA-256，数据库只保存元数据和文件标识；
- 图书馆管理工作台保留“馆藏管理”“借还办理”“借阅查询”切换标签，移除上方重复标题与说明，内容区上移以增加可用高度；
- 图书价格只在详情页显示为“遗失赔偿参考价”，列表和借阅页不显示；管理员异常归还前必须先获取服务器费用预估；
- 存在 `PENDING` 图书账单时禁止新借和续借，但允许归还、查账和缴费；缴费必须先显示费用明细、银行余额及冻结状态并二次确认；
- 论坛使用独立 CSS 的原生 JavaFX 首页、帖子详情、发帖编辑器和管理员内容管理；发帖可上传、预览、排序最多三张图片；帖子与评论可举报，举报消息发送给所有已启用的论坛管理员和超级管理员；管理员在举报队列中驳回、隐藏或删除内容后，所有关联举报者收到处理结果，举报成立时被处理内容的实际作者收到警告（评论只通知评论作者，不误通知楼主）；内容管理可软删除帖子或评论，管理员删帖通知作者，帖子设为校园公告时通知所有启用用户并排除操作管理员；后台入口只对论坛管理员和超级管理员显示；
- 论坛按钮文字为黑色，浅蓝选中态；可用内容区不足 1080px 收起右侧公告/热榜，保留公告入口；最小窗口下按钮文字不省略、管理页可滚动；
- 日常评论列表对所有角色只显示正常评论；作者删除不可恢复，管理员隐藏可恢复；审核记录仅在管理页保留；
- 点赞/收藏不发消息；回复通知按收件人去重且不通知自己；公告与置顶分别管理；
- 除论坛管理员和超级管理员外，拥有论坛访问权限的用户可为他人的正常、非公告、非置顶帖子选择 5/10/15 元助力；其他业务管理员仍显示入口；点击档位即自动扣费且成功后不退款，支付期间防重复提交；作者、限额、冻结或余额不足等状态显示服务端原因；
- 论坛“热门”和“今日热榜”加入 12 小时半衰期、48 小时失效的助力热度，管理员置顶仍优先，“最新”仍按发布时间排序；
- 论坛通知支持来源筛选和指定帖子深链；关联帖子不可访问时给出可读提示并返回论坛首页；
- 银行提供 B1 余额工作台（无个性化问候）、T1 填写—核对—结果三步转账（无自填备注）、本人流水，以及按权限显示的账户管理和全量流水；日期、类型、关键字与业务编号由服务端筛选，收支汇总覆盖完整结果；交易结果未知时保留原编号与参数重试；冻结账户不能转账或消费，但仍能收款、退款和查询；
- 银行通知支持来源筛选并直达本人流水页；论坛助力成功通知固定归入银行区域，正文含金额、初始热度、余额和 `FB-` 参考号；
- 银行账户管理在宽屏固定左右分栏、窄屏上下排列；核对账号后，选中账户面板不会因滚动条或像素取整反复换行；
- 商店以图片卡片展示商品，首页商品卡显示平均星级和评价数；商品详情同时提供“加入购物车”“立即购买”、五星分布和评价列表；评价仅能基于本人已完成的订单商品创建，每个订单商品至多一条，重复购买按订单事实标记“回购”；评价含必选 1—5 星、5—1000 字正文和最多三张 JPG/PNG/WebP 图片；
- 公开评价仅展示正常状态，按点赞数、创建时间和评价 ID 依次降序；用户不能点赞自己的评价，点赞为目标状态幂等操作且不发通知；作者可以编辑或软删除，商店管理员和超级管理员填写 2—255 字原因后隐藏或恢复，审核记录保留；
- 商店提供购物车、订单确认、我的订单，以及按权限显示的商品管理、订单管理和评价管理页签；新商品货号由服务端自动生成，管理员可上传、排序并设置最多五张 JPG/PNG 商品图，支付、退款和发货通知可直达原生订单详情；
- 工作台根据基础身份和附加角色显示“学/师、教、书、商、银、论”，学籍管理员教师显示七张卡片并支持滚动；
- 左侧导航适配桌面端，顶部显示当前页面和登录用户；检索保留在具体业务模块中；
- 学生与教师课表采用星期一至星期日、每天 12 节的图形表格；
- 管理员排课通过课表格子选择时段，已占用且周次重叠的教师时间不可选择；
- 不照搬移动端尺寸与底部手势区，保持桌面应用的键鼠可用性；门户最小窗口为 1000×720，较长内容可滚动。
- 查询和刷新按钮统一使用浅色背景、深色粗体文字，避免系统外观导致文字对比度不足。
- 只有超级管理员在“工作台”下方看到“账号管理”和“系统管理”，普通学生、教师及业务管理员均不显示；服务端仍对每次系统管理请求独立校验权限；
- 账号管理提供学生/教师账号创建、角色分配、启停和密码重置，不提供删除及超级管理员创建功能。
- 系统管理只编辑业务日历与作息，不向客户端暴露数据库凭据、Socket 端口、线程数或附件目录等部署配置；审计页只读，不提供删除或修改历史记录；记录详情使用无内部滚动的两行四列横排字段布局。
