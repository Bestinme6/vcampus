# 虚拟教务管理设计

## 功能范围

- 教务管理员分页查询、新增、编辑、启用和停用课程；
- 教务管理员按专业、连续入学年份和版本维护培养方案，并在方案中批量设置必修/选修与建议学期；
- 教务管理员复制、发布和归档培养方案；已发布版本不可直接修改，同一专业生效年份不能重叠；
- 教务管理员创建教学班和招生范围，通过星期一至星期日、每天 12 节的图形课表维护排课草稿；
- 排课草稿经服务端教师/教室冲突校验后发布，发布前学生和教师不可见；
- 教务管理员开放或关闭教学班、查看名单并发布成绩；
- 学生按本人专业、入学年份匹配培养方案，在每门课程下选择具体教学班，并可退选或原子切换教学班；
- 系统校验容量、重复课程和时间冲突，并用数据库事务维护已选人数；
- 学生使用 7 天 × 12 节图形课表查看本人课程，并查询已发布成绩；
- 教师使用同样的图形课表查看本人全部授课时段；
- 管理员选择教师和周次后，教师已占用的时间格会被禁用；服务端额外校验教师和教室冲突；
- 教师查看自己的教学班与学生名单，录入、修改并发布本人教学班的成绩；
- 成绩修改写入历史记录，发布后不允许继续修改或重新开放教学班；
- 超级管理员拥有教务管理和教师演示权限。

当前学期通过 `database/seed.sql` 初始化。本轮已实现围绕学期开展的完整教务流程，学期新建与日期维护界面留作后续增强，不影响课程演示。

## 三层教务模型

```text
全校课程 courses
    -> 培养方案课程 curriculum_plan_courses（必修/选修、建议学期）
        -> 学期教学班 course_sections（教师、容量、招生范围、排课与成绩）
```

管理员新增课程时只定义稳定的课程号、名称、学分和学时，不在全校课程上选择“必修/选修”。课程加入某个专业培养方案时才确定该方案下的属性，因此同一门课可以在计算机专业为必修、在其他专业为选修，不需要为每个年级重复创建课程。连续入学年份共用一个发布版本；教学安排变化则新建教学班，不复制课程或培养方案。

## 角色界面

| 角色 | 可见页签 |
| --- | --- |
| 学生 | 选课中心、我的课程、我的课表、我的成绩 |
| 教师 | 教师课表、任课班级、成绩管理 |
| 教务管理员（必须同时是教师） | 课程库、培养方案、开课管理、智能排课、发布中心；同时保留教师功能 |
| 超级管理员 | 全部学生、教师和教务管理演示页面 |

服务端会对每个动作重新校验会话和角色。多角色账号会同时看到相应页签，客户端可见性不是权限判断的唯一依据。

## 数据库结构

| 表 | 作用 |
| --- | --- |
| `academic_terms` | 学年、学期、选课时间、退课截止时间和学期状态 |
| `courses` | 课程号、课程名、学分、学时和启用状态 |
| `curriculum_plans` | 专业、适用连续入学年份、版本、草稿/发布/归档状态和发布审计 |
| `curriculum_plan_courses` | 培养方案内的课程、必修/选修属性和建议学期 |
| `course_sections` | 教学班、任课教师、容量、人数、状态和成绩发布状态 |
| `course_section_targets` | 教学班允许选择的专业与连续入学年份范围 |
| `course_section_schedule_revisions` | 教学班排课的草稿、发布版本与操作者 |
| `class_schedules` | 隶属某个排课版本的星期、节次、周次和教室 |
| `course_enrollments` | 学生选课、退课状态和时间 |
| `grades` | 分数、绩点、评语、提交人与发布时间 |
| `grade_change_history` | 成绩每次变更的旧值、新值、修改人和原因 |

新数据库依次执行最新的 `database/schema.sql` 和 `database/seed.sql`。已经初始化过的数据库应先停服并备份，再按顺序执行尚未应用的迁移；本轮教务升级对应 `database/migrations/014_academic_curriculum_javafx.sql`。迁移会建立培养方案、招生范围和排课版本数据，并把已有教学班课表回填为发布版本；不要通过重建数据库来绕过迁移。

## 主要业务规则

JavaFX “我的校园”使用 `academic.referenceData` 中新增的 `term.N.startDate` 和 `term.N.endDate`（ISO 日期）判断所属学期，再按星期和教学周筛选课表。原 `term.N` 仍是三字段 RowCodec 行，旧业务面板兼容；门户和服务端需要一起更新。课程只显示第几节，不推测作息钟点；日期不在任何学期内时不查询当日课表。

- 课程号必须采用 `C` 加 6 位数字，例如 `C000001`；课程号作为稳定业务编号，创建后不可修改，编辑课程只修改名称、学分、学时、说明和启用状态；必修/选修不属于全校课程；
- 培养方案由专业、连续入学年份范围和版本号标识；只有草稿可修改课程，发布前必须至少包含一门课程，发布版本不可变，需通过“复制新版本”继续调整；
- 同一专业的已发布方案适用年份不得重叠；学生只匹配本人专业和入学年份对应的发布方案；
- 教学班可面向一个或多个专业与入学年份范围；学生必须同时满足培养方案和教学班招生范围；
- 排课保存只更新草稿，发布时使用预期修订号防止覆盖其他管理员的新版本，并再次校验教师与教室冲突；
- 只有处于选课状态、教学班为开放状态且当前时间位于选课区间内时，学生才能选课；
- 同一学期不能同时选择同一门课程的两个教学班；
- 换班同时锁定原教学班、新教学班和本人选课记录；容量、时间或资格检查失败时，原选课与双方人数保持不变；网络结果不确定时客户端重新加载服务端状态，不盲目回滚；
- 一个教学班可以包含多个每周上课时段；每个时段限定为星期一至星期日、第 1—12 节；
- 星期、节次和周次存在交叉的教学班不能同时选择；
- 同一教师或同一教室在周次和节次重叠时不能重复排课；
- 教学班满员后不允许继续选课；选退课锁定教学班记录并在同一事务内更新人数；
- 退课必须早于学期退课截止时间，成绩发布后不能退课；
- 成绩范围为 0–100，系统按统一规则换算 0.0–4.0 绩点；
- 任课教师可以发布本人教学班的成绩，教务管理员和超级管理员可以代为发布；必须为所有在选学生录入成绩后才能发布；发布后教学班转为完成状态，成绩只读。

## 在 Eclipse 中验收

1. 新数据库执行 `database/schema.sql` 和 `database/seed.sql`；旧数据库先备份，再执行尚未应用的迁移，至少确认 `014_academic_curriculum_javafx.sql` 已成功完成；
2. 回到 Eclipse，选中父项目后按 `F5`，再执行 `Project -> Clean`；
3. 停止旧进程，先运行 `com.vcampus.server.ServerMain`，再运行 `com.vcampus.client.ClientMain`；
4. 使用超级管理员登录原生教务工作区，在“课程库”新增或确认一门启用课程；课程此时不选择必修/选修；
5. 在“培养方案”创建草稿，选择专业与连续入学年份，加入课程并设置必修/选修和建议学期，然后发布；需要改版时使用“复制新版本”；
6. 在“开课管理”新增教学班并设置招生范围，再进入“智能排课”保存草稿、处理冲突并发布；确认冲突格不可选，发布前学生不可见；
7. 使用匹配专业和年级的学生账号登录，在“选课中心”的课程分组下选择一个教学班，再切换到同课程另一教学班，检查 7 天 × 12 节的“我的课表”；
8. 用任课教师或超级管理员登录，检查“教师课表”，再在“授课与成绩”中打开名单并录入成绩；
9. 任课教师在“授课与成绩”中点击“发布最终成绩”，也可用教务管理员或超级管理员在“教学班与发布”中代为发布；
10. 最后使用学生账号登录，在“我的成绩”中确认课程、分数和绩点。

若教学班没有出现在选课中心，请依次检查：迁移 `014` 是否完成、培养方案是否已发布且匹配学生专业/入学年份、课程是否启用、教学班招生范围是否匹配、课表是否已发布、学期是否处于 `SELECTION`、教学班是否为 `OPEN`，以及当前时间是否在选课区间。

默认运行 `ClientMain` 使用原生 JavaFX 教务工作区；`ClientMain --swing` 或 `scripts/run-client.ps1 -Swing` 保留旧 `AcademicModulePanel` 作为兼容入口。教务通知可直达学生/教师课表、学生成绩或管理员指定教学班排课页。所有 Socket 操作在后台执行器运行，JavaFX Application Thread 只更新界面；注销和切页会使迟到响应失效。
