# 教师个人信息设计

## 功能范围

- 教师工作台第一张基础身份卡片显示“师 / 教师信息”；
- 教师查看本人的教师工号、姓名、学院、职称、电话和邮箱；
- 教师工号、姓名、学院和职称只读；
- 教师可以修改本人电话和邮箱；
- 网络和数据库请求在后台线程执行，Swing 界面更新回到事件分发线程；
- 操作成功对话框统一使用“操作成功”标题。

超级管理员没有个人教师档案入口。拥有学籍管理员角色的教师会在“师 / 教师信息”前额外看到“学 / 学籍管理”，工作台因此显示七张卡片并可滚动。

## 数据库结构

`teacher_profiles` 通过唯一 `user_id` 关联账号，保存教师工号、姓名、学院、职称、电话和邮箱。已经初始化过数据库的环境可重新执行最新 `database/schema.sql` 补建该表，不会删除已有数据。

## 服务动作

| Action | 权限 | 说明 |
| --- | --- | --- |
| `profile.teacher.getSelf` | 教师 | 查询当前账号关联的教师档案 |
| `profile.teacher.updateContact` | 教师本人 | 修改当前教师的电话和邮箱 |

两个动作都要求有效会话，并在服务端重新确认基础身份为教师。教师账号若缺少 `teacher_profiles` 记录，界面会给出可读错误；超级管理员现在可通过“账号管理”在同一事务中创建教师账号、角色和教师档案。

## 工作台名称

- 普通教师：师/教师信息、教/教学管理、书/图书借阅、商/商店购物、银/线上银行、论/校园论坛；
- 教务、图书、商店、银行或论坛管理员：对应卡片标题改为相应“管理”；
- 学籍管理员教师：在普通教师卡片前增加“学/学籍管理”；
- 学生：学/学籍信息、教/课程安排、书/图书借阅、商/商店购物、银/线上银行、论/校园论坛；
- 超级管理员：学/学籍管理、教/教务管理、书/图书管理、商/商店管理、银/银行管理、论/论坛管理。
