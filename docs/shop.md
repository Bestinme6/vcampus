# 校园商店使用与验收说明

## 功能与角色

学生和教师可以浏览已上架商品、维护持久购物车、使用虚拟银行余额结算，并查看、取消或确认自己的订单；确认收货后可选择立即评价或稍后评价。所有登录用户还可以在二手市场发布本人闲置物品、购买他人物品、处理本人出售订单和评价卖家。商店管理员和超级管理员额外拥有普通商品管理，以及二手物品、异常订单和评价审核权限。服务端始终根据当前会话确定买家、卖家、评价作者或操作人，客户端不能伪造用户 ID 操作他人的物品、购物车、订单或评价。

## 页面与状态

- 普通页签：商品列表、二手市场、购物车、我的订单、收货地址；二手市场内部提供“发布物品 / 我的购买 / 我的出售”；
- 管理页签：商品管理、订单管理、评价管理；
- 新建商品时货号由服务端在保存后按数据库商品 ID 自动生成，格式为 `SKU-000001`；客户端货号框只读，编辑商品时原货号保持不变；
- 订单管理按订单号或买家用户名（学生账号即学号）检索；列表和详情显示“姓名（用户名/学号）”，不向客户端展示数据库内部买家 ID；
- 消息中心的支付、退款和发货通知可直接打开对应订单详情；
- 默认客户端的商店为原生 JavaFX + CSS：列表使用图片卡片，点击后进入商品详情；详情同时提供“加入购物车”和“立即购买”，后者进入订单确认页且不修改原购物车；
- 收货地址簿最多保存三条，普通商店与二手商店共用；保存第四条时必须明确选择并确认覆盖。购物车结算和立即购买都可以选择一条已保存地址，也可以填写仅本次使用的新地址，并可选择保存；
- 管理员可为每件商品上传、拖动排序、设置封面或删除最多五张图片；图片编辑失败不会替换服务端原有图片计划；
- Socket 和图片文件请求均在后台线程执行，完成后回到 JavaFX 应用线程更新界面；新增的二手市场只提供 JavaFX + 外部 CSS 界面，不增加或扩展 Swing 二手页面。

商品首页卡片显示正常评价的平均分和评价数量；没有评价时显示“暂无评分”。商品详情显示平均分、五星分布和评价列表，公开列表由服务端按点赞数量降序、创建时间降序、评价 ID 降序返回，客户端不再次排序。评价卡显示 1—5 星、购买已验证、可选回购/已编辑标识、正文、最多三张图片和“有帮助”数量。

评价规则：

- 只允许订单买家评价状态为 `COMPLETED` 的订单商品，一个订单商品至多创建一条评价；同一商品的后续已完成订单会被服务端标记为回购；
- 创建请求使用 UUID 幂等编号，网络结果未知时复用编号与已完成的上传编号，不重复创建评价或图片；
- 星级必选 1—5，正文去除首尾空白后为 5—1000 字，图片可选且最多三张；
- 作者可编辑正常评价或软删除；删除后仍占用原订单商品的评价资格；
- 用户不能点赞自己的评价；点赞请求明确发送目标状态，重复启用或取消不会重复计数，也不产生消息通知；
- 商店管理员和超级管理员可按关键字、状态和页码检索评价，填写 2—255 字原因后隐藏或恢复；隐藏/删除评价不参与公开列表、平均分、数量和五星分布。

订单状态为：已支付 `PAID`、已发货 `SHIPPED`、已完成 `COMPLETED`、已取消 `CANCELLED`。买家只能取消已支付订单，只能确认已发货订单；管理员只能发货已支付订单。商品下架后仍保留在已有购物车中，但结算会由服务端拒绝。

## 二手共享市场

- 所有已登录用户都可以发布二手物品；标题、描述、分类、成色和价格由服务端校验。只有物品本人可以修改、下架或上传图片，并且物品必须仍为 `AVAILABLE/VISIBLE`；不能购买本人发布的物品；
- 二手物品图片与普通商品图片隔离存储，每件最多五张且必须明确唯一封面。客户端按分块协议上传，提交图片计划失败时不会部分替换元数据；
- 买家可选择共享地址簿中的地址及版本，或填写一次性新地址并选择保存；订单只保存地址快照，列表、通知和评价不携带完整地址。只有订单买家、卖家和有权限的管理员能读取订单详情地址；
- 购买时先从买家余额扣款并记为 `SECONDHAND_HOLD` 冻结资金，同时将物品原子地改为已预订。卖家只能为本人的 `PAID` 订单发货；买家确认收货后，冻结资金以 `SECONDHAND_PAYOUT` 入账卖家。买家在发货前取消，或管理员裁决退款时，以 `SECONDHAND_REFUND` 退回买家；
- 购买、评价和管理员异常订单处理分别使用稳定 UUID。网络结果未知时必须复用原 UUID；数据库唯一约束保证不会重复冻结、退款、结算或创建评价；
- 取消的可见物品重新变为可购买。管理员只能对已发货异常订单二选一执行“退款并重新上架”或“结算给卖家”，必须填写 2—255 字原因并显式确认；处理日志和资金流水同事务提交；
- 已完成订单的买家可以对卖家评价一次，1—5 星、正文 5—1000 字、最多三张图片；其他用户可以标记“有帮助”。卖家评分显示在物品卡片，隐藏或删除评价不参与评分；
- 商店管理员和超级管理员可以带原因隐藏或恢复二手物品、隐藏或恢复评价，并处理异常订单。客户端只发送物品、订单或评价 ID，不发送买家或卖家 ID，最终权限始终由服务端会话判定；
- 二手订单通知使用 `SECONDHAND_ORDERS` 目标，可从 JavaFX 消息中心直接打开 `used-order/<id>` 对应详情。

## 结算、退款与库存规则

- 商品价格和订单金额使用 MySQL `DECIMAL(15,2)` 与 Java `BigDecimal`；
- 购物车只保存商品 ID 和数量，展示及结算使用商品当前价格；
- 结算由服务端重新读取价格，并按商品 ID 固定顺序锁定商品，避免并发超卖；
- 每次结算使用 UUID 业务编号，唯一约束保证网络重试不会重复生成订单或扣款；
- 结算必须提交已保存地址的槽位与版本，或提交完整的新地址；服务端在扣款前重新校验并把收件人、联系电话和详细地址保存为订单不可变快照。旧订单没有地址快照时仍可查看，并明确显示“历史订单无收货地址”；
- 银行扣款、支付流水、订单、不可变商品快照、库存扣减、库存流水、购物车清理和 `SHOP_ORDER_PAID` 回执使用同一个 JDBC `Connection`，全部成功才提交；
- 取消订单使用下单时的冻结金额退款，即使商品后来改价也不受影响；退款流水、库存恢复、库存流水、订单状态和 `SHOP_ORDER_REFUNDED` 回执同事务提交；
- 冻结账户不能购物，结算时明确提示“账户已冻结，不能支付”，但仍可接收取消订单退款；
- 发货状态和 `SHOP_ORDER_SHIPPED` 通知同事务提交，重复发货不会重复通知。

库存流水类型包括初始入库 `INITIAL`、管理员调整 `ADMIN_ADJUST`、订单销售 `SALE` 和取消回库 `ORDER_CANCEL`。历史订单商品名称、货号、单价、数量和小计使用结算快照，不随商品编辑变化。

## Socket 动作

普通动作：`shop.product.search`、`shop.product.get`、`shop.image.getChunk`、`shop.cart.get`、`shop.cart.setQuantity`、`shop.cart.remove`、`shop.address.list`、`shop.address.save`、`shop.address.delete`、`shop.buyNow`、`shop.checkout`、`shop.order.search`、`shop.order.get`、`shop.order.cancel`、`shop.order.confirm`。

管理员动作：`shop.admin.product.save`、`shop.admin.product.setEnabled`、`shop.admin.inventory.adjust`、`shop.admin.order.search`、`shop.admin.order.ship`、`shop.admin.image.upload.start`、`shop.admin.image.upload.chunk`、`shop.admin.image.upload.complete`、`shop.admin.image.commit`。所有动作均由服务端校验会话、参数和权限。

评价动作：`shop.review.list`、`shop.review.create`、`shop.review.update`、`shop.review.delete`、`shop.review.like.set`；评价图片动作为 `shop.review.image.upload.start`、`shop.review.image.upload.chunk`、`shop.review.image.upload.complete`、`shop.review.image.getChunk`；管理员动作为 `shop.admin.review.search`、`shop.admin.review.hide`、`shop.admin.review.restore`。

二手市场动作使用 `shop.used.` 前缀，包括物品 `item.search/get/create/update/withdraw`、物品图片 `image.upload.start/chunk/complete` 与 `image.commit/getChunk`、订单 `order.buy/search/get/cancel/ship/confirm`、评价 `review.list/create/update/delete/like.set` 及对应评价图片动作。管理员动作包括 `admin.item.hide/restore`、`admin.order.search/get/resolve` 和 `admin.review.search/hide/restore`。所有写操作均从会话确定操作者。

## 环境和数据库

服务端继续使用项目统一的数据库环境变量：

```powershell
$env:VCAMPUS_DB_URL = 'jdbc:mysql://127.0.0.1:3306/vcampus?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
$env:VCAMPUS_DB_USER = '你的数据库用户名'
$env:VCAMPUS_DB_PASSWORD = '你的数据库密码'
$env:VCAMPUS_SHOP_IMAGE_DIR = 'D:\vcampus-data\shop-images'
$env:VCAMPUS_SHOP_REVIEW_IMAGE_DIR = 'D:\vcampus-data\shop-review-images'
$env:VCAMPUS_SECONDHAND_IMAGE_DIR = 'D:\vcampus-data\secondhand-images'
$env:VCAMPUS_SECONDHAND_REVIEW_IMAGE_DIR = 'D:\vcampus-data\secondhand-review-images'
```

`VCAMPUS_SHOP_IMAGE_DIR` 必须指向应用服务器可读写的专用目录；不配置时使用服务端默认的 `data/shop-images`。目录只保存规范化图片文件，MySQL 仅保存图片元数据。正式支持 JPG/JPEG 与 PNG，单张不超过 2 MiB、解码像素不超过 20,000,000，每件商品最多五张，上传分块不超过 192 KiB。

客户端图片缓存默认位于 `user.home/.vcampus/cache/shop`，可用 `VCAMPUS_SHOP_CACHE_DIR` 覆盖；缓存会按服务端 SHA-256 校验，损坏或缺失图片只显示占位图，不影响商品文字和购买操作。

评价图片使用独立的 `VCAMPUS_SHOP_REVIEW_IMAGE_DIR`，未配置时为 `data/shop-review-images`；支持真实 JPG/JPEG、PNG 与 WebP，单张不超过 5 MiB、解码像素不超过 20,000,000，上传分块不超过 192 KiB。客户端评价缓存默认为 `user.home/.vcampus/cache/shop-reviews`，可用 `VCAMPUS_SHOP_REVIEW_CACHE_DIR` 覆盖。

二手物品和二手评价图片分别使用 `VCAMPUS_SECONDHAND_IMAGE_DIR` 与 `VCAMPUS_SECONDHAND_REVIEW_IMAGE_DIR`，未配置时为 `data/secondhand-images` 与 `data/secondhand-review-images`。目录必须位于应用服务器可读写的专用位置，不得放入客户端或数据库；物品图片限制与普通商品一致，评价图片限制与普通商品评价一致。

当前商店及银行联动表结构由服务端启动时按资源指纹检查并应用。已有数据库升级前先备份，统一流程见 `docs/delivery-guide.md`；历史编号迁移仅用于特殊旧库追溯，不是演示现场的常规步骤。

种子脚本创建三个虚构商品并为仍属于 `OTHER` 的旧演示记录补充学习文具或校园周边分类；管理员已设置的非 `OTHER` 分类不会被覆盖。商品说明和价格可安全更新，初始库存通过固定种子原因只增加一次，因此重复执行不会覆盖管理员调整后的库存，也不会重复写初始库存流水。

## 手工验收

1. 启动 MySQL 和应用服务器，再打开两个普通客户端、一个商店管理员客户端和一个银行管理员客户端；
2. 银行管理员为两位普通用户准备余额，确认冻结用户不能结算；
3. 普通用户把商品加入购物车，退出再登录，确认购物车仍存在；
4. 在收货地址页依次保存三条地址；保存第四条时确认未选覆盖项或未勾选确认均不能提交，明确选择后只替换目标槽位；
5. 分别使用已保存地址、仅本次使用的新地址和保存后的新地址完成购买；修改或删除地址簿记录后，确认历史订单仍显示下单时的地址快照；
6. 管理员改价后再结算，确认订单使用服务器上的当前价格并保存快照；
7. 验证空购物车、下架商品、库存不足和余额不足均失败，且余额、库存、流水和购物车没有部分变化；
8. 两个用户同时购买最后一件库存，确认只有一笔已支付订单和一笔支付流水；
9. 使用同一个结算 UUID 重试，确认返回原订单且不重复扣款、重复发送支付通知；从支付通知直接打开对应订单详情；
10. 买家取消已支付订单，确认退款、回库、两类流水、订单状态和退款通知一起变化；重复取消不重复退款或通知；从退款通知直接打开对应订单详情；
11. 管理员发货，买家收到商店通知并能直达对应订单详情；买家确认收货后状态为已完成；
12. 修改商品名称和价格，确认历史订单详情仍显示原快照；
13. 普通用户调用商店管理员动作应被拒绝，其他用户不能读取或取消该订单；
14. 管理员分别输入订单号片段和买家用户名/学号检索订单，确认列表与详情不显示买家内部 ID；
15. 管理员连续新建两个商品，确认无需输入货号且得到不同的 `SKU-六位数字`；编辑其中一个商品后确认货号不变；
16. 在隔离测试库验证服务端重复启动不会重复增加种子库存或初始库存流水；
17. 管理员上传五张 JPG/PNG，排序并切换封面后保存、重连，确认顺序和封面持久化；再测试伪装成图片的文本、超过 2 MiB 文件及中断上传，确认旧图片未被替换；
18. 两个普通客户端并发购买最后一件库存，确认只有一笔支付；分别验证立即购买不改变购物车、购物车只结算已勾选商品；
19. 从支付、退款和发货通知进入订单详情，确认打开的是同一原生 JavaFX 商店实例，返回后回到工作台。
20. 完成两个同商品订单，确认第一条评价无回购标识、后续订单评价显示“回购”，且一个订单商品不能重复评价；
21. 分别选择确认收货后的“立即评价”和“稍后评价”，创建 1—5 星、零图和三图评价，重连后编辑并软删除；
22. 另一用户点赞并重复提交相同目标状态，确认数量只变化一次，且公开列表按点赞数、创建时间、评价 ID 排序；作者点赞自己的评价应被拒绝；
23. 管理员填写原因隐藏和恢复评价，确认公开列表、首页平均分/数量及详情五星分布同步变化，删除状态只读，审核记录存在；
24. 中断评价创建响应后使用同一 UUID 和上传编号重试，确认数据库只有一条评价和一组图片；验证伪装文件、超过 5 MiB、超像素和跨用户上传编号均被拒绝。
25. 普通用户发布二手物品并上传图片；另一用户能检索和查看，发布者不能购买本人物品，其他用户不能修改、下架或替换图片；
26. 买家分别使用已保存地址和一次性地址购买，确认地址簿与普通商店共用、订单保留快照，列表、通知和评价不泄露地址；并发购买同一物品时只有一笔成功冻结资金；
27. 卖家在“我的出售”查看该订单地址并发货，其他卖家不能查看或发货；买家从消息中心打开同一订单并确认收货，确认卖家只入账一次；
28. 买家在发货前取消，确认冻结资金退款且可见物品重新上架；管理员对已发货异常订单分别演练退款和结算，重复 UUID 不重复记账；
29. 买家完成订单后创建带图评价，另一用户点赞，确认物品卡片卖家评分变化；管理员隐藏与恢复评价后评分同步变化；
30. 商店管理员隐藏与恢复二手物品并检查原因；普通用户调用 `shop.used.admin.*` 被拒绝，客户端请求不包含买家或卖家 ID。

## 验证记录

- 普通商店及二手市场的 JavaFX、图片、共享地址、资金托管、订单、评价与管理端专项测试通过；普通商店视觉基线详见 `docs/design/javafx-shop/design-qa.md`；
- 当前根项目统一自动化基线见 `docs/testing.md`；
- 客户端源码 JDBC 扫描无匹配，保持 MySQL -> 应用服务器 -> JavaFX 客户端三层结构；
- 最终交付环境仍需按上节完成多客户端并发资金、库存与附件目录人工验收。
