# 校园商店使用与验收说明

## 功能与角色

学生和教师可以浏览已上架商品、维护持久购物车、使用虚拟银行余额结算，并查看、取消或确认自己的订单。商店管理员和超级管理员额外拥有商品新建与编辑、上架与下架、带原因的库存调整、全部订单检索和发货权限。服务端始终根据当前会话确定买家或操作人，客户端不能伪造用户 ID 操作他人的购物车或订单。

## 页面与状态

- 普通页签：商品列表、购物车、我的订单；
- 管理页签：商品管理、订单管理；
- 消息中心的商店发货通知可直接打开“我的订单”；
- Socket 请求均在后台线程执行，完成后回到 Swing 事件线程更新界面；请求期间按钮禁用，浅色按钮使用黑色文字。

订单状态为：已支付 `PAID`、已发货 `SHIPPED`、已完成 `COMPLETED`、已取消 `CANCELLED`。买家只能取消已支付订单，只能确认已发货订单；管理员只能发货已支付订单。商品下架后仍保留在已有购物车中，但结算会由服务端拒绝。

## 结算、退款与库存规则

- 商品价格和订单金额使用 MySQL `DECIMAL(15,2)` 与 Java `BigDecimal`；
- 购物车只保存商品 ID 和数量，展示及结算使用商品当前价格；
- 结算由服务端重新读取价格，并按商品 ID 固定顺序锁定商品，避免并发超卖；
- 每次结算使用 UUID 业务编号，唯一约束保证网络重试不会重复生成订单或扣款；
- 银行扣款、支付流水、订单、不可变商品快照、库存扣减、库存流水和购物车清理使用同一个 JDBC `Connection`，全部成功才提交；
- 取消订单使用下单时的冻结金额退款，即使商品后来改价也不受影响；退款流水、库存恢复、库存流水和订单状态同事务提交；
- 冻结账户不能购物，但仍可接收取消订单退款；
- 发货状态和 `SHOP_ORDER_SHIPPED` 通知同事务提交，重复发货不会重复通知。

库存流水类型包括初始入库 `INITIAL`、管理员调整 `ADMIN_ADJUST`、订单销售 `SALE` 和取消回库 `ORDER_CANCEL`。历史订单商品名称、货号、单价、数量和小计使用结算快照，不随商品编辑变化。

## Socket 动作

普通动作：`shop.product.search`、`shop.cart.get`、`shop.cart.setQuantity`、`shop.cart.remove`、`shop.checkout`、`shop.order.search`、`shop.order.get`、`shop.order.cancel`、`shop.order.confirm`。

管理员动作：`shop.admin.product.save`、`shop.admin.product.setEnabled`、`shop.admin.inventory.adjust`、`shop.admin.order.search`、`shop.admin.order.ship`。所有动作均由 `ShopService` 校验会话、参数和权限。

## 环境和数据库

服务端继续使用项目统一的数据库环境变量：

```powershell
$env:VCAMPUS_DB_URL = 'jdbc:mysql://127.0.0.1:3306/vcampus?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
$env:VCAMPUS_DB_USER = '你的数据库用户名'
$env:VCAMPUS_DB_PASSWORD = '你的数据库密码'
```

全新数据库依次执行 `database/schema.sql` 和 `database/seed.sql`。旧数据库先备份，再依次执行 `database/migrations/007_bank.sql`、`database/migrations/008_shop.sql`，最后执行最新的 `database/seed.sql`。不要只执行 008：商店结算依赖 007 创建的银行账户与流水结构。

种子脚本创建三个虚构商品。商品说明和价格可安全更新，初始库存通过固定种子原因只增加一次，因此重复执行不会覆盖管理员调整后的库存，也不会重复写初始库存流水。

## 手工验收

1. 启动 MySQL 和应用服务器，再打开两个普通客户端、一个商店管理员客户端和一个银行管理员客户端；
2. 银行管理员为两位普通用户准备余额，确认冻结用户不能结算；
3. 普通用户把商品加入购物车，退出再登录，确认购物车仍存在；
4. 管理员改价后再结算，确认订单使用服务器上的当前价格并保存快照；
5. 验证空购物车、下架商品、库存不足和余额不足均失败，且余额、库存、流水和购物车没有部分变化；
6. 两个用户同时购买最后一件库存，确认只有一笔已支付订单和一笔支付流水；
7. 使用同一个结算 UUID 重试，确认返回原订单且不重复扣款；
8. 买家取消已支付订单，确认退款、回库、两类流水和订单状态一起变化；重复取消不重复退款；
9. 管理员发货，买家收到商店通知并能直达“我的订单”；买家确认收货后状态为已完成；
10. 修改商品名称和价格，确认历史订单详情仍显示原快照；
11. 普通用户调用商店管理员动作应被拒绝，其他用户不能读取或取消该订单；
12. 连续执行两次 `seed.sql`，确认三个商品的库存和初始库存流水第二次不再增加。

本任务不替用户启动服务端或改动本机 MySQL。上述数据库和多客户端场景需由用户启动本机环境后人工联调。
