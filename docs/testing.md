# VCampus 测试指南

测试分为三层：默认自动化测试、显式启用的真实 MySQL 集成测试，以及按业务闭环执行的人工验收。

## 1. 默认自动化测试

在关闭运行中的服务端和客户端后执行完整验证：

```powershell
mvn clean verify
```

开发中的快速复测可执行：

```powershell
mvn test
```

当前基线（2026-09-13）：根项目 `mvn clean verify` 共执行 930 项测试，0 失败、0 错误、9 跳过。跳过项是需要外部环境的测试，不代表对应业务尚未实现。

模块级复测示例：

```powershell
mvn -pl vcampus-common test
mvn -pl vcampus-server -am test
mvn -pl vcampus-client -am test
```

如需只运行某个测试类，可在对应模块使用 Maven Surefire 的 `-Dtest=<测试类名>`。测试类名应以当前源码为准，不在本文固化易过期的类名列表。

## 2. 真实 MySQL 集成测试

数据库自动准备的真实 MySQL 测试默认不启用。测试会在配置的 MySQL 实例上创建随机命名的临时数据库，并在结束时删除；所用临时账号需要创建/删除数据库以及测试用户的权限，因此不得使用演示库的低权限应用账号，也不应在生产实例执行：

```powershell
$env:VCAMPUS_BOOTSTRAP_MYSQL_TEST = "true"
$env:VCAMPUS_DB_URL = "jdbc:mysql://127.0.0.1:3306/vcampus_test_control?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai"
$env:VCAMPUS_DB_USER = "<临时测试管理员>"
$env:VCAMPUS_DB_PASSWORD = "<临时测试密码>"
mvn -pl vcampus-server -am test
```

约束：

- 不得把集成测试指向演示库或生产数据。
- 控制库必须预先存在；测试源码只删除自己创建且名称匹配 `vcampus_test_<随机值>` 的数据库。
- 测试账号仅在隔离 MySQL 实例或明确的测试维护窗口使用，测试结束后撤销。
- 密码只保存在当前进程环境中，不进入命令历史文件或仓库。
- 具体安全边界以 `DatabaseBootstrapperMysqlTest` 的当前源码为准。

## 3. 人工验收

人工验收以跨角色、跨模块的业务闭环为单位，而不是只确认页面能打开。推荐直接按 [演示指南](demo-guide.md) 彩排，并在相关模块文档中补充边界场景。

当前记录：

- 默认 JavaFX 主流程已具备自动化覆盖。
- 消息中心核心真实 MySQL 双客户端流程已于 2026-09-10 验证：学生与超级管理员之间完成消息读取、重新标未读、再次读取、未读角标 `0 → 1 → 0`，并确认收件人隔离。
- 其余模块仍应在最终交付环境完成一次完整跨角色人工验收；这是发布验收项，不表示功能未实现。

人工验收至少覆盖：

- 登录、首次改密、退出与会话失效
- 超级管理员创建账号、分配角色、启停账号
- 超级管理员修改节次时间，学生或教师刷新课表后看到真实钟点；普通用户的系统管理请求被拒绝
- 按用户、动作前缀、结果和日期查询审计日志，确认配置变更可追溯且审计记录不可编辑
- 分别执行银行转账/管理、商店订单/库存、教务培养方案/排课/选退课/成绩和论坛删除/审核关键操作，确认统一审计保留原动作码、操作者和稳定结果码；随后执行列表与详情查询，确认不新增审计噪声
- 选择和清空审计表格记录，确认下方八个详情字段按两行四列横排显示、空值为 `—`，且详情区没有文本输入框或内部滚动条
- 在学生教务工作区分别进入“选课中心”和“我的课程”，确认前者展示可选课程并负责首次选课，后者只展示已选课程并提供退课与合格教学班换班，两个入口内容不同
- 使用教师、教务管理员和银行管理员账号确认教务、银行均为顶部两级页签；切换一级板块后只显示对应二级功能，教务“授课与成绩”可查看任课班级并打开成绩册
- 教务选课/退课、成绩录入与学生查询
- 图书借阅/预约/归还及通知
- 银行充值或调整、商店下单扣款及流水一致性
- 论坛发帖、审核、互动与权限边界
- 消息发布、已读/未读、删除、分页、角标与收件人隔离
- 服务端重启后的数据持久化和客户端恢复

## 4. 测试结果判定

- 自动化测试失败：先定位失败原因，不以人工点击代替。
- 因外部依赖而跳过：在交付记录中写明依赖和补测方式。
- 人工流程失败：记录账号角色、操作顺序、服务端日志时间点和数据库备份版本。
- 视觉测试输出写入模块 `target/visual-snapshots`；如需人工更新设计基线，必须单独复制并确认差异，自动测试不得改写 `docs/design` 中的受控截图。
