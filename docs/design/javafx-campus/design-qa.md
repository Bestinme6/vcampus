## 行为与架构

- 保持 MySQL → 应用服务器 → 桌面客户端三层 C/S，复用 MessageCodec 协议。
- 首次改密完成前不进入校园，不请求个人业务数据；登录结束清空密码输入。
- 日期依据 Asia/Shanghai，课程按学期日期、教学周和星期筛选；缺少日期元数据时提示，不猜测学期。
- 学生和教师只查询本人数据；超级管理员显示管理入口，不查询个人消费或课表。
- 只读 `bank.account.summary` 不开户、不变更资金；原银行业务入口仍按需开户。服务端继续检查会话、首次改密与角色。
- JavaFX 回调受会话、日期代次保护；日期查询有独立的会话执行器，取消过时任务，并在请求之间检查取消，避免阻塞新登录。
- Swing 兼容层关闭时使组件失效，抑制迟到结果、对话框及后续请求；已发往服务器的操作可能完成，注销不代表撤销已提交交易。
- 未读刷新使用已测试的不重叠轮询器，退出时关闭；网络错误显示提示，不伪装成零条记录或零余额。

2026-08-31 最终 `clean verify` 退出码为 0：公共模块 56 项、服务端 183 项、客户端 134 项，共 **373 项测试，0 失败、0 错误、0 跳过**。新增用例重现并覆盖慢查询积压后重新登录、迟到消息详情、账号及排课校验弹窗中退出的场景。定向代码复查已确认上述生命周期问题修复。

已人工检查本目录列出的各尺寸截图：展开登录连接设置时可纵向滚动；首次改密字段和按钮完整；校园小窗口的待办换行正常，长页面可滚动。大礼堂保持浅蓝建筑线稿风格。

最终 Windows 运行包通过 `scripts/run-client.ps1 -CheckRuntime`（退出码 0）；另执行启动脚本运行 JavaFX 客户端，客户端结束时退出码为 0。此启动检查没有进行真实数据库登录。

根目录运行 `mvn clean verify`（本机使用 `.tools/maven-settings.xml`）。JUnit 使用真实回环 Socket/MessageCodec、内存数据库和桌面 UI 线程，覆盖输入校验、强制改密、迟到登录撤销、日期切换与注销隔离、原有权限和业务行为。JavaFX 测试位于 classpath，会输出 unnamed-module 提示；Windows 启动脚本使用 JavaFX module-path，另以 `-CheckRuntime` 验证模块解析。

截图由测试写入 `vcampus-client/target/javafx-qa`，完成检查后复制到本目录。请在具有桌面图形环境、Java 21 的 Windows 上运行界面测试；无图形环境的服务器不能直接执行这些 JavaFX/Swing UI 用例。

此次不修改数据库结构，不替用户启动或写入本机 MySQL。真实 MySQL 登录、跨账号消息深链、多客户端资金和教务业务验收尚需按各模块文档进行。自动化通过不等同于完成真实数据库验收。
