# 图书费用与银行支付联动设计

**日期：** 2026-09-14  
**状态：** 已批准
**范围：** 图书逾期、破损与遗失计费，银行主动缴费，消息中心通知

## 1. 目标

在保持“MySQL 数据库 → 应用服务器 → Swing/JavaFX 客户端”三层结构的前提下，为图书模块增加费用账单，并通过银行模块完成用户主动缴费。

本功能应满足：

- 图书逾期、破损或遗失时按明确规则生成费用；
- 用户能在图书详情中提前看到遗失赔偿参考价；
- 管理员办理归还或遗失时先看到费用预览；
- 系统先生成账单，只有用户主动确认后才扣款；
- 账单、银行流水和消息具有完整的一致性、幂等性与审计记录；
- 余额不足、账户冻结或网络重试不得造成借阅状态错误或重复扣款。

## 2. 已确认的业务规则

### 2.1 赔偿参考价

- 每个书目维护一个“赔偿参考价”，它不是图书售价。
- 用户只在图书详情页看到该价格；馆藏列表、搜索结果和普通借阅列表不显示。
- 图书管理员或超级管理员在新建、编辑书目时维护该价格。
- 新书目的赔偿参考价必填，必须不低于 `0.01` 元，并保留两位小数。
- 历史书目允许迁移后暂时没有价格，但在管理员办理破损或遗失前必须补齐。
- 账单保存生成时的参考价快照。后续调整书目价格不会改变已有账单。

### 2.2 逾期计费

- 应还日期后的第 1 天为宽限期，不收费。
- 从第 2 天开始，每天收取 `0.50` 元。
- 单次借阅的逾期费用最高为 `20.00` 元。
- 未归还时只展示实时逾期状态与预估费用，不生成金额持续变化的正式账单。
- 正常归还、破损归还或登记遗失并关闭借阅时，按服务器时间计算最终逾期费用。

逾期计费公式：

```text
计费天数 = max(0, 逾期自然日数 - 1)
逾期费用 = min(计费天数 × 0.50, 20.00)
```

逾期自然日数以服务器配置时区中的日期边界计算，避免客户端时钟差异影响金额。

### 2.3 破损与遗失计费

- 轻微破损：赔偿参考价的 `20%`。
- 严重破损：赔偿参考价的 `50%`。
- 无法继续流通：按遗失处理，收取赔偿参考价的 `100%`。
- 登记破损或遗失时，管理员必须填写原因。
- 管理员选择破损等级后由服务器自动计算金额，不允许直接输入任意金额。
- 百分比计算结果按银行模块的金额规则保留两位小数。

### 2.4 组合计费

同一本书既逾期又破损或遗失时，两类费用同时收取并合并到同一张账单。例如：

```text
逾期费       ¥5.00
严重破损费  ¥40.00
合计        ¥45.00
```

账单必须分别保存并展示各费用项目，不能只显示总额。

### 2.5 零金额与未缴限制

- 正常按期归还且无破损时，不创建零金额账单。
- 存在待缴图书账单时，用户不能新增借阅或续借。
- 待缴账单不影响归还、查看账单、查看图书或进行缴费。

## 3. 总体架构

采用“独立图书费用账单 + 银行支付接口”的联动方式：

- 图书模块负责计费规则、费用预览、账单生成、账单管理和借阅限制。
- 银行模块负责账户校验、实际扣款、退款及银行流水。
- 消息中心负责发送账单生成、缴费成功、减免和退款通知，并提供到图书费用页或银行流水的导航。
- 图书模块不得直接执行银行账户 SQL；银行支付能力通过服务端端口接口暴露。
- 客户端不得直接连接数据库，所有金额均由服务器重新计算和验证。

图书费用支付流程：

```text
用户查看待缴账单
  → 客户端展示服务端返回的费用明细和账户余额
  → 用户二次确认并提交唯一操作编号
  → 服务器锁定账单和银行账户
  → 银行扣款并写入流水
  → 图书账单改为已缴费
  → 写入缴费成功通知
  → 同一事务提交
```

## 4. 数据设计

### 4.1 书目价格

`books` 增加：

- `replacement_price DECIMAL(10,2) NULL`：遗失赔偿参考价。

完整建库脚本和增量迁移必须同时更新。种子书目应补充合理的演示价格；不得用统一的虚假默认价格覆盖现有数据。

### 4.2 费用政策

新增单例配置表 `library_fee_policy`，至少包含：

- 宽限天数；
- 每日逾期费用；
- 单次逾期费用上限；
- 轻微破损比例；
- 严重破损比例；
- 无法流通/遗失比例；
- 最后修改人和修改时间。

初始值分别为 `1` 天、`0.50` 元、`20.00` 元、`20%`、`50%` 和 `100%`。只有图书管理员和超级管理员可以修改；每次修改都写入审计记录。

### 4.3 图书费用账单

新增 `library_fee_bills`，至少保存：

- 账单 ID 与唯一账单编号；
- 借阅记录 ID、借阅人用户 ID、书目 ID 与馆藏副本 ID；
- 账单状态：`PENDING`、`PAID`、`WAIVED`、`REFUNDED`；
- 逾期费、破损费、遗失费和总额；
- 逾期天数、计费天数和破损等级；
- 赔偿参考价、每日费率、费用上限和比例等规则快照；
- 管理员登记的异常原因；
- 生成者、生成时间、缴费时间、减免/退款操作者及原因；
- 对应的付款银行业务编号和退款银行业务编号。

账单与借阅记录建立唯一约束，保证一次借阅关闭最多产生一张费用账单。账单总额必须等于费用项之和且大于零。

首版不新增独立的账单事件表。账单保存当前状态和各状态时间，减免、退款等管理操作通过现有系统审计记录完整留痕。

### 4.4 银行流水

银行流水类型增加：

- `LIBRARY_FEE`：图书费用扣款；
- `LIBRARY_REFUND`：图书费用退款。

流水引用编号使用账单编号或基于账单编号生成的稳定退款编号，并通过现有银行业务唯一约束保证幂等。账单保存对应流水编号，用户可以从图书账单跳转查看银行流水。

### 4.5 消息中心词汇

增加通知类型：

- `LIBRARY_FEE_CREATED`：图书费用待缴；
- `LIBRARY_FEE_PAID`：图书费用缴费成功；
- `LIBRARY_FEE_WAIVED`：费用已减免；
- `LIBRARY_FEE_REFUNDED`：费用已退款。

待缴通知跳转到图书模块的费用账单；缴费或退款通知可同时携带银行流水引用编号。

## 5. 服务端行为

### 5.1 费用预览

管理员提交归还或遗失前，服务器根据借阅记录、服务器当前时间、书目参考价和当前政策返回预览。客户端只负责展示，不能自行决定最终金额。

管理员最终确认时，服务器必须重新读取并锁定相关记录、重新计算费用，防止预览后状态或规则变化。最终回执中的金额为准。

### 5.2 关闭借阅并生成账单

借阅关闭、馆藏状态更新、账单生成和待缴通知在同一数据库事务中完成：

- 正常归还：馆藏恢复可借；若有逾期费用则生成账单。
- 破损归还：馆藏变为破损，生成破损费及可能的逾期费账单。
- 无法流通或遗失：馆藏变为遗失，生成遗失费及可能的逾期费账单。
- 任一 SQL、通知写入或规则校验失败时，全部回滚。

### 5.3 用户缴费

- 缴费请求必须携带 UUID 格式的唯一操作编号。
- 服务器按固定顺序锁定账单和付款账户，避免并发死锁。
- 仅 `PENDING` 账单可以支付，且必须由账单所属用户发起。
- 服务器再次校验账单总额，不接收客户端提交的可变金额。
- 账户余额不足时返回“余额不足，账单仍待缴”。
- 账户冻结时返回“银行账户已冻结，暂时无法缴费”。
- 支付成功后，扣款、银行流水、账单状态和通知同一事务提交。
- 对同一操作编号的重试返回原结果；不同操作编号并发支付时只能有一次扣款成功。

### 5.4 减免与退款

- 图书管理员和超级管理员可以减免尚未支付的账单，必须填写原因。
- 已缴账单不能改为减免，只能发起退款。
- 退款金额等于该账单的原实付金额，首版不支持部分退款。
- 退款写入独立银行入账流水，并将账单改为 `REFUNDED`。
- 退款不得超过原实付金额，重复退款必须被拒绝或幂等返回原结果。
- 冻结账户允许接收退款，保持与银行模块“冻结账户可入账、不可出账”的语义一致。

## 6. 客户端体验

### 6.1 普通用户

- 图书列表和搜索结果保持原布局，不显示价格。
- 图书详情增加“遗失赔偿参考价”和“该价格仅用于遗失或严重破损赔偿，不是售价”的说明。
- 借阅确认中提示遗失将按当前参考价计费，但不需要再次显示具体价格。
- “我的借阅”增加“待缴费用”入口或分区，展示账单项目、计算依据、总额、状态和异常原因。
- 用户点击“立即缴费”后看到费用明细、银行余额及二次确认。
- 支付成功后展示银行流水编号并刷新账单、余额和未缴限制状态。
- 余额不足、账户冻结和网络错误显示准确且可恢复的提示，不得统一显示“无法连接”。

### 6.2 图书管理员

- 书目新建和编辑页增加“赔偿参考价”。
- 借还办理页在最终确认前展示服务端费用预览。
- 破损归还要求选择轻微或严重；无法继续流通使用遗失处理。
- 破损和遗失必须填写原因。
- 新增费用账单管理，支持按用户、书名、条码、账单编号和状态查询，并执行减免或退款。
- 费用政策配置只对图书管理员和超级管理员可见。

### 6.3 消息跳转

- `LIBRARY_FEE_CREATED` 点击后进入对应图书费用账单。
- `LIBRARY_FEE_PAID`、`LIBRARY_FEE_REFUNDED` 可进入账单详情，并允许继续跳转到银行流水。
- 若账单已经改变状态，页面显示最新状态，不重复触发支付。

## 7. 协议与权限

共享模块新增以下稳定的 `library.*` 动作及必要枚举/记录：

- `library.fee.my`：分页查询本人费用账单；
- `library.fee.get`：查询本人账单详情；
- `library.fee.payment.preview`：获取缴费确认信息和当前银行余额；
- `library.fee.pay`：支付本人待缴账单；
- `library.admin.fee.search`：管理员分页查询全部账单；
- `library.admin.fee.preview`：预览归还、破损或遗失费用；
- `library.admin.fee.waive`：减免待缴账单；
- `library.admin.fee.refund`：退回已缴账单；
- `library.admin.fee-policy.get`：读取当前费用政策；
- `library.admin.fee-policy.update`：修改费用政策。

所有权限由服务端重新校验：

- 普通用户只能查看和支付自己的账单；
- 图书管理员和超级管理员可以管理政策、账单、减免和退款；
- 银行管理员不能仅凭银行角色修改图书账单；
- 客户端隐藏按钮不能替代服务端权限控制。

上述动作名称通过协议兼容测试锁定，不得由客户端使用字符串字面量自行拼接。

## 8. 一致性、幂等与并发

- 关闭借阅与账单生成必须原子化。
- 缴费、扣款流水、账单状态和通知必须原子化。
- 减免或退款、账单状态、银行流水和通知必须原子化。
- 账单编号、支付操作编号和银行流水业务引用分别建立唯一约束。
- 两个客户端同时支付同一账单时，只有一个请求改变状态并扣款；另一个返回“账单已缴清”。
- 请求超时后的重试不得生成第二张账单、第二次扣款或第二条同类通知。
- 金额始终使用 `BigDecimal` 和 SQL `DECIMAL`，禁止使用浮点数。

## 9. 错误处理

预期业务错误必须以安全、明确的中文消息返回，例如：

- “该书目尚未设置赔偿参考价”；
- “账单已缴清”；
- “余额不足，账单仍待缴”；
- “银行账户已冻结，暂时无法缴费”；
- “存在待缴图书费用，暂时不能借书或续借”；
- “只有待缴账单可以减免”；
- “该账单已经退款”。

数据库异常、协议错误或未知服务器错误不得伪装成余额不足等业务提示，也不得把 SQL、表名或堆栈信息返回客户端。

## 10. 测试与验收

### 10.1 规则测试

- 按期归还和宽限期内归还均不收费。
- 第 2 个逾期日开始收费，达到 `20.00` 元后不再增加。
- 轻微、严重、无法流通/遗失分别按 `20%`、`50%`、`100%` 计算。
- 逾期与破损/遗失正确组合，金额项目之和等于总额。
- 金额舍入统一为两位小数。
- 修改价格或政策后，旧账单快照和金额不变。

### 10.2 服务与权限测试

- 普通用户不能查看或支付他人账单。
- 非图书管理员不能修改政策、减免或退款。
- 有待缴账单时借阅和续借被阻止，但归还仍成功。
- 没有参考价时破损/遗失预览返回可恢复的业务错误。
- 零金额归还不创建账单。

### 10.3 事务与并发测试

- 账单通知写入失败时归还、馆藏状态和账单全部回滚。
- 银行扣款或通知失败时账单保持待缴且余额不变。
- 相同操作编号重试只产生一笔扣款。
- 两个线程支付同一账单只产生一笔银行流水。
- 退款失败时账单仍为已缴费，余额不增加。

### 10.4 客户端测试

- 价格只在图书详情和管理员编辑页显示。
- 费用预览、组合明细、待缴状态和支付确认显示正确。
- 消息中心能跳转到对应账单。
- 余额不足、冻结和网络异常分别显示正确提示。
- JavaFX 状态更新留在 FX Application Thread，网络和数据库工作不阻塞 UI 线程。

### 10.5 全量验证

- 执行模块测试及根目录 `mvn clean verify`。
- 执行 `git diff --check`。
- 在 MySQL 环境验证建库脚本和增量迁移。
- 使用两个普通用户客户端和一个图书管理员客户端验证费用生成、并发支付、限制借阅、减免、退款及消息跳转。

## 12. 非目标

首版不包括：

- 分期或部分缴费；
- 用户申诉审批工作流；
- 对接外部图书定价网站或采购系统；
- 按单个馆藏副本维护不同采购价；
- 现金、微信或支付宝等银行模块之外的支付方式；
- 逾期期间每天生成一张新账单。
