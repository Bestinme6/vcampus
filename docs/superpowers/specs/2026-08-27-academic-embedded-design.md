# 教务模块嵌入设计

## 目标

将工作台“教”模块显示在 `MainFrame` 右侧内容区，并将教师课表、学生成绩通知深链改为复用同一个嵌入式教务模块。

## 范围与约束

- 提取 `AcademicModulePanel`，保留课程、教学班、选课、学生课表、学生成绩、教师课表和授课成绩页签。
- 页签仍由 `AcademicAccessPolicy` 按角色决定。
- “教学班与发布”页签被激活时仍调用 `refreshReferences()`。
- 通知深链分别选择“教师课表”和“我的成绩”。
- 原 `AcademicFrame` 保留为薄兼容窗口。
- 不修改服务端、数据库、协议和教务业务逻辑。

## 路由与生命周期

`MainModuleRoute` 将 `ACADEMIC` 映射为 `academic`。`MainFrame` 首次访问时创建一个 `AcademicModulePanel`，后续工作台和通知深链均复用它；返回工作台不销毁面板，因此当前页签和筛选状态得以保留。

`AcademicModuleNavigation` 根据实际页签标题查找深链目标。目标页签不存在时不改变选中项，权限拦截仍由 `MainFrame` 在导航前执行。

## 验收标准

1. 点击“教”不产生新窗口，右侧显示角色允许的教务页签。
2. 返回并重新进入时复用原面板。
3. 教师课表通知定位“教师课表”。
4. 学生成绩通知定位“我的成绩”。
5. 教学班参考数据刷新行为保持不变。
6. 所有操作弹窗行为保持不变，`mvn clean verify` 全部通过。
