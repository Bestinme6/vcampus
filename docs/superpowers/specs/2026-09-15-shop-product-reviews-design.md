# 商店商品评价功能设计

- 日期：2026-09-15
- 状态：已完成交互设计，等待书面规格复核
- 范围：校园商店商品评价、评分汇总、评价图片、点赞与内容管理

## 1. 背景与目标

当前校园商店已支持商品浏览、购物车、结算、发货、确认收货和商品图片，但已完成订单无法沉淀购买体验。本功能在商品详情中增加与真实订单绑定的评价，并在商店首页商品卡片展示评分摘要。

目标如下：

- 只有完成真实购买的用户能够评价对应商品；
- 每个已完成订单商品明细最多产生一条评价；
- 评价包含 1～5 星、文字、可选图片和“有帮助”点赞；
- 商品首页和详情展示可信、实时的评分汇总；
- 评价按点赞数量从高到低稳定排列；
- 重复购买可以再次评价，并明确标记“回购评价”；
- 图片、网络和数据库处理继续遵守服务端边界与异步 UI 规则。

## 2. 非目标

第一版不实现以下功能：

- 评价回复、商家回复和追加评价；
- 评价举报工作流；
- 点赞、评价或管理操作的消息中心通知；
- 推荐算法、情感分析或基于评分的商品排序；
- 将商店评价存入论坛帖子或评论表；
- 为旧 Swing 兼容入口新增完整评价界面。服务端协议保持独立，默认 JavaFX 商店是本次 UI 交付目标。

## 3. 核心产品规则

1. 评价绑定 `shop_order_items`，而不是只绑定用户与商品。
2. 当前会话必须是订单买家，订单状态必须为 `COMPLETED`，才可评价订单商品。
3. 一个订单商品明细最多评价一次；同一用户再次完成同一商品的另一笔订单后，可以再次评价。
4. 创建评价时，如果同一买家存在同商品的另一笔更早完成订单，则保存 `repeat_purchase=true`，详情中显示“回购评价”。先按 `completed_at` 判断先后，同一时间再按订单 ID 判断；该值创建后不随未来订单变化。
5. 星级必选且为 1～5 的整数；去除首尾空白后的文字必须为 5～1000 个字符。
6. 图片可选，每条评价最多 3 张，按用户指定顺序展示。
7. 作者可以修改自己的正常评价，包括星级、文字和图片；界面显示“已编辑”，原有点赞保留。
8. 作者可以软删除自己的正常评价；已删除评价不可恢复，也不能再次占用同一订单商品创建新评价。
9. 商店管理员和超级管理员可以因违规内容隐藏正常评价，或恢复隐藏评价。操作必须填写 2～255 字原因并保留审计记录。管理员不能物理删除差评。
10. 只有 `NORMAL` 状态评价参与列表、平均分、评价数和星级分布。
11. 每个用户对每条正常评价最多有一条点赞记录，并且不能给自己的评价点赞。
12. 点赞接口提交明确的目标状态，重复提交相同状态不重复计数。

## 4. 架构与模块职责

### 4.1 `vcampus-common`

- 在 `Actions` 中增加 `shop.review.*` 和 `shop.admin.review.*` 动作；
- 增加评价状态等共享枚举；
- 继续使用 `MessageCodec` 与 `RowCodec`，不使用 Java 原生对象序列化；
- 协议只携带业务标识，不允许客户端上传评价人 ID、商品平均分、回购标记或点赞总数等服务端事实。

### 4.2 `vcampus-server`

- `ShopReviewService`：会话、权限、参数和业务规则校验，组装协议响应；
- `ShopReviewStore` / `ShopReviewRepository`：评价事务、列表、汇总、点赞和审核数据访问；
- `ShopReviewImageService`：临时上传、格式验证、缩略图、正式提交、分块读取和垃圾文件清理；
- `RequestRouter`：路由新增动作；
- 现有 `ShopService` / `ShopRepository`：商品搜索和详情响应增加评分摘要，订单详情增加评价资格；
- 可复用论坛图片处理的稳定底层能力，但评价数据表、权限、服务和文件目录保持独立。

### 4.3 `vcampus-client`

- `ShopData`：增加评分摘要、评价、评价分页、评价图片和订单商品评价资格模型；
- `ShopGateway` / `SocketShopGateway`：增加评价、点赞、审核和图片接口；
- `ShopController`：所有 Socket 与图片请求在后台执行，完成后回到 JavaFX 应用线程；
- `ShopProductCard`：显示平均分与评价数量；
- `ShopDetailView`：显示评分摘要、星级分布和评价分页；
- 新增评价编辑器，支持星级、文字、图片预览、排序和移除；
- `ShopOrderDetailView`：对可评价商品显示“去评价”，确认收货成功后显示“立即评价 / 稍后评价”；
- `ShopAdminView`：增加评价管理入口，支持检索正常、隐藏和已删除记录，以及隐藏、恢复操作。

## 5. 数据模型

### 5.1 `shop_product_reviews`

主要字段：

- `id BIGINT` 主键；
- `operation_id VARCHAR(64)` 唯一，用于创建评价幂等；
- `order_item_id BIGINT` 唯一，外键指向 `shop_order_items`；
- `product_id BIGINT`，外键指向 `shop_products`；
- `author_user_id BIGINT`，外键指向 `users`；
- `rating TINYINT`，检查范围 1～5；
- `content VARCHAR(1000)`，检查去除首尾空白后长度为 5～1000；
- `repeat_purchase BOOLEAN`；
- `status VARCHAR(16)`，取值 `NORMAL`、`HIDDEN`、`DELETED`；
- `created_at`、`updated_at`、`deleted_at`。

索引覆盖商品可见评价列表、作者历史评价和管理端状态检索。数据库唯一约束作为服务端校验之外的最终防重边界。

### 5.2 `shop_review_images`

字段包括评价 ID、位置、原图及缩略图存储键、MIME 类型、字节数、SHA-256、宽高和创建时间。`(review_id, position)` 唯一，位置限制为 0～2。

### 5.3 `shop_review_likes`

以 `(review_id, user_id)` 为联合主键，记录创建时间。外键删除策略保留评价软删除场景所需的历史关系；正常业务不物理删除评价。

### 5.4 `shop_review_moderation_logs`

记录评价 ID、操作者、`HIDE` 或 `RESTORE` 动作、原因和操作时间。审核日志只读，不随评价状态变化删除。

## 6. 协议动作与响应扩展

普通动作：

- `shop.review.list`
- `shop.review.create`
- `shop.review.update`
- `shop.review.delete`
- `shop.review.like.set`
- `shop.review.image.upload.start`
- `shop.review.image.upload.chunk`
- `shop.review.image.upload.complete`
- `shop.review.image.getChunk`

管理员动作：

- `shop.admin.review.search`
- `shop.admin.review.hide`
- `shop.admin.review.restore`

现有响应扩展：

- `shop.product.search` 的每个商品增加 `ratingAverage` 与 `ratingCount`；无评价时平均分为空、数量为 0；
- `shop.product.get` 增加平均分、评价总数和 1～5 星数量；
- `shop.order.get` 的每个订单商品增加 `reviewable` 与可选 `reviewId`。

评价列表默认每页 10 条。每行包含作者显示名、星级、正文、图片引用、回购标记、点赞数、当前用户是否点赞、创建及更新时间。不得返回用户名、学号或数据库内部用户 ID。

## 7. 关键数据流

### 7.1 确认收货与评价入口

确认收货仍只负责将 `SHIPPED` 订单变为 `COMPLETED`。成功后客户端弹出非阻塞提示，让用户选择“立即评价”或“稍后评价”。关闭提示不会改变评价资格，用户可从订单详情逐项进入评价。

### 7.2 创建评价

1. 客户端完成可选图片临时上传并保留上传 ID；
2. 客户端生成 UUID 操作编号，提交订单商品 ID、星级、正文和有序上传 ID；
3. 服务端在事务中锁定订单商品及所属订单，验证买家、完成状态和唯一性；
4. 服务端根据更早的已完成同商品订单计算回购标记；
5. 服务端写入评价和图片元数据并提交；
6. 提交后图片才进入正式关联状态；失败时不产生半条评价；
7. 网络结果不确定时客户端复用原 UUID，服务端返回首次创建结果。

商品是否当前上架不影响已完成订单的评价资格。下架商品的评价继续保留，重新上架后恢复正常展示。

### 7.3 修改与删除

修改时服务端重新校验作者、`NORMAL` 状态、正文、星级和图片计划。数据库提交失败时保留旧评价及旧图片集合。成功后更新 `updated_at`，点赞关系不变。

删除将状态变为 `DELETED` 并填写 `deleted_at`，不物理删除评价、图片和点赞历史。删除后立即退出公开列表和评分统计。

### 7.4 点赞

`shop.review.like.set` 接收评价 ID 和 `enabled`。服务端验证评价正常可见且操作者不是作者，然后插入或删除联合主键记录。相同目标状态重复执行返回成功且不改变计数。

### 7.5 审核

管理员隐藏或恢复评价时，在同一事务中更新状态并写审核日志。隐藏、恢复和重复目标状态均有明确结果；重复请求不得重复写审计记录。

## 8. 汇总与排序

首页和详情评分不保存为可漂移的固定平均值，而由服务端对 `NORMAL` 评价聚合：

- `ratingAverage = AVG(rating)`，协议与界面保留一位小数；
- `ratingCount = COUNT(*)`；
- 详情额外返回 1～5 星各自数量。

评价列表排序固定为：

1. 点赞数降序；
2. 创建时间降序；
3. 评价 ID 降序。

查询通过评价商品/状态索引和点赞联合键聚合。首版不增加额外统计缓存表；测试数据规模下优先保证一致性。若未来实际数据量证明聚合成为瓶颈，再单独设计事务化统计缓存。

## 9. 图片规则

- 支持 JPG、PNG 和 WebP；
- 单张原文件不超过 5 MiB；
- 每条评价最多 3 张；
- 服务端检查文件签名、完整解码和像素上限，并生成缩略图；
- 每个上传分块不超过 192 KiB；
- 解码后的图片像素总数不超过 20,000,000；
- 服务端目录由 `VCAMPUS_SHOP_REVIEW_IMAGE_DIR` 配置，默认 `data/shop-review-images`；
- 客户端缓存与商品图片、论坛图片分开，按 SHA-256 校验；
- 损坏或缺失图片显示占位图，不影响文字、星级和点赞操作；
- 未关联临时上传在完成上传 30 分钟后清理，数据库已提交文件不得被临时清理任务删除。

## 10. 界面设计

### 10.1 商品首页

商品卡片在名称下方显示黄色星级、保留一位小数的平均分和评价数，例如 `★★★★★ 4.8（36 条评价）`。无正常评价时显示“暂无评分”，不显示虚假的 0 星。

### 10.2 商品详情

商品购买信息下方增加评价区：

- 左侧或顶部为平均分、星级和 1～5 星分布；
- 右侧或下方为“最有帮助的评价”列表；
- 每条评价显示作者昵称、已购、可选回购标签、星级、正文、图片、日期、已编辑状态和“有帮助”按钮；
- 图片支持缩略图和大图查看；
- 分页控件位于列表底部。

窄窗口改为单列：评分摘要位于评价列表之前。评价异步加载失败不影响商品图片、价格、库存、加入购物车和立即购买。

### 10.3 评价编辑器

编辑器显示对应商品与订单信息、1～5 星选择、文字计数、最多三张图片的添加/排序/移除、提交错误和上传进度。离开未提交表单时提示确认，失败后保留草稿。

### 10.4 管理端

评价管理按商品名称、作者显示名和状态检索。隐藏和恢复均使用带原因的确认面板；管理端能查看隐藏和已删除记录，但公开商品详情只返回正常评价。

## 11. 错误处理与安全

- 未登录、越权订单、未完成订单、重复评价、无效星级、正文越界和图片违规返回可理解的中文错误；
- 创建 UUID 冲突时只返回属于同一用户、同一订单商品的原结果，否则拒绝；
- 唯一约束冲突转换为“该订单商品已评价”，不暴露 SQL 细节；
- 隐藏或删除状态评价的更新、点赞请求被拒绝；
- 客户端不能提交作者、回购标记、评价状态、点赞数或评分汇总；
- 所有数据库访问仅在服务端完成；
- 文件路径由服务端生成和规范化，客户端不能提供存储路径；
- 日志不得记录图片内容、真实个人资料或敏感配置。

### 12.4 总体与人工验收

## 14. 验收标准

功能完成时必须同时满足：

1. 未完成真实购买的用户无法评价；
2. 每个已完成订单商品只能评价一次，重复购买可产生回购评价；
3. 首页和详情评分与当前正常评价严格一致；
4. 评价能携带最多三张安全校验后的图片；
5. 点赞幂等且列表按点赞数、时间、ID 稳定排序；
6. 修改、删除、隐藏和恢复立即影响公开列表与统计，审计记录完整；
7. 网络重试、并发请求和失败回滚不产生重复或部分数据；
8. JavaFX 界面在目标窗口宽度下可用，后台工作不阻塞 UI；
9. `mvn clean verify` 通过，并完成 MySQL 多客户端人工验收；
10. 需求、商店说明、schema 和迁移保持同步。
