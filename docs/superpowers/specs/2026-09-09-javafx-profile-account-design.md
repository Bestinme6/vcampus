# VCampus 学籍与账号原生 JavaFX 改造设计

## 1. 背景与目标

VCampus 门户、教务、图书馆、商店、银行和论坛已经使用原生 JavaFX，学籍管理、学生本人学籍、账号管理和教师本人信息仍通过 `SwingNode` 嵌入 Swing 面板。四个页面在字体、间距、弹窗、加载反馈和窗口缩放方面与现有 JavaFX 模块不一致，也使门户同时维护 JavaFX 与 Swing 两套页面生命周期。

本次改造将这四个页面替换为原生 JavaFX 页面，在不改变业务规则的前提下统一视觉和交互：

- 学籍管理采用“紧凑列表 + 右侧详情”的管理界面；
- 学生本人学籍和教师本人信息采用留白充足的资料卡片；
- 账号管理采用“筛选列表 + 右侧操作区”，集中完成创建、角色、启停和密码重置；
- 所有网络请求离开 JavaFX Application Thread，所有控件更新回到 JavaFX Application Thread；
- 工作台入口、左侧导航和学籍消息深链直接进入新页面，不再经过 `SwingNode`。

## 2. 范围与边界

### 2.1 本次包含

- 学籍管理员和超级管理员使用的学籍管理页面；
- 学生查看本人学籍及修改本人联系方式的页面；
- 超级管理员使用的账号管理页面；
- 教师查看本人信息及修改本人联系方式的页面；
- 上述页面的 JavaFX 表单、确认框、结果反馈、加载状态、空状态和错误状态；
- 门户路由、消息深链、页面缓存和退出登录时的资源释放；
- 客户端响应解析、权限显示策略、控制器测试和关键宽度截图检查；
- README、需求基线和相关模块文档的状态更新。

### 2.2 本次不包含

- 数据库表、种子数据、协议动作或服务端业务规则的变更；
- 新增账号删除、基础身份转换或超级管理员创建功能；
- 新增学生档案创建入口，学生与教师账号仍由超级管理员在账号管理中统一创建；
- 将旧 Swing 类立即删除。旧类继续供 `--swing` 等兼容启动方式使用，但 JavaFX 门户不再为这四条路由创建对应 Swing 页面。

## 3. 角色与路由

| 使用者 | 入口 | JavaFX 页面 | 权限 |
| --- | --- | --- | --- |
| 学生 | 工作台“学籍” | 本人学籍 | 只读本人基础与学业信息，可修改本人联系方式、查看本人状态历史 |
| 教师 | 工作台“教师信息” | 教师本人信息 | 只读工号、学院和职称，可修改本人联系方式 |
| 学籍管理员 | 工作台“学籍管理” | 学籍管理 | 查询与维护学生档案、联系方式、学籍状态和状态历史 |
| 超级管理员 | 工作台“学籍管理” | 学籍管理 | 与学籍管理员相同 |
| 超级管理员 | 左侧“账号管理” | 账号管理 | 创建普通账号、修改附加角色、启停账号、重置密码 |
| 学生 | 学籍类消息“查看学籍信息” | 本人学籍 | 直接定位本人学籍页面 |

客户端入口隐藏只改善体验。服务端继续对每个现有动作执行最终权限校验，客户端不复制或放宽服务端规则。

## 4. 统一视觉语言

四个页面沿用门户现有蓝白配色和 `FxStyles` 基础控件，增加一份身份资料模块样式表。页面背景使用浅灰蓝，内容放在白色圆角卡片中；主要操作使用校园蓝，普通操作使用浅色按钮，停用等高风险操作使用克制的红色文字和边框。

统一组件包括：

- 页面标题、简短说明和返回工作台按钮；
- 带图标或首字头像的身份卡；
- 标签和值组成的详情行；
- 启用、停用、在籍、休学等状态徽标；
- 搜索栏、筛选框、分页栏和结果总数；
- 加载骨架或加载提示、无数据空状态、页内错误提示和重试按钮；
- JavaFX 模态表单、确认框及成功提示。

在 1440 像素内容宽度下，管理页面使用列表与详情双栏；在约 1220 像素时缩小详情栏和字段间距；在约 1000 像素时保持主要操作可见，允许表格横向滚动，详情区不挤压表格列。本人资料页限制内容最大宽度并居中，避免宽屏时信息过度拉散。响应式规则以实际内容区宽度为准，不依赖屏幕分辨率。

## 5. 页面设计

### 5.1 学籍管理

页面顶部提供关键词、学籍状态筛选、查询和刷新。关键词继续匹配现有服务端支持的学号、姓名等字段；状态选项复用现有枚举和中文显示，不新增客户端伪分类。

主体左侧为紧凑学生表格，显示学号、姓名、学院、专业、行政班、状态和联系方式摘要。点击一行后，右侧详情卡展示完整基础信息、学业归属和联系方式。分页栏显示当前页、总页数和总记录数；筛选变化后回到第一页。

右侧操作按现有 `StudentManagementActionPolicy` 显示：

- 编辑档案：修改允许维护的姓名、性别、出生日期、学院、专业、行政班和入学年份；
- 编辑联系方式：修改电话、邮箱和地址；
- 变更学籍状态：选择新状态并填写原因，提交前明确展示“当前状态 → 新状态”；
- 状态历史：以时间线显示状态、原因、操作者和时间。

学院、专业和行政班继续使用服务端参考数据并保持级联关系。保存成功后重新获取该学生详情并刷新当前列表，保持当前筛选和选中学生；若记录已不符合筛选条件，则清除详情并给出说明。

### 5.2 学生本人学籍

页面顶部身份卡展示姓名、学号和当前学籍状态。下方按“基本信息”“学业信息”“联系方式”分成三张卡片：

- 基本信息：姓名、性别、出生日期；
- 学业信息：学院、专业、行政班、入学年份、学籍状态；
- 联系方式：电话、邮箱、地址。

只有联系方式卡显示编辑按钮。状态历史使用纵向时间线，默认放在资料卡下方；无历史记录时显示明确空状态。保存联系方式后原位刷新卡片，避免整页跳转。

### 5.3 账号管理

页面顶部提供关键词、基础身份和启用状态筛选。主体左侧表格显示账号、姓名、基础身份、附加管理员角色、启用状态、是否强制改密和最后登录时间。表格不显示超级管理员。选中账号后，右侧操作卡显示完整角色与状态，并提供以下动作：

- 创建账号：先选择学生或教师，再显示对应资料字段、合法附加角色和临时密码；
- 修改角色：基础身份只读，只能勾选该身份允许的附加管理员角色；
- 启用或停用：显示目标账号、姓名和状态变化，确认后提交；
- 重置密码：输入并确认新的临时密码，不显示或回传旧密码。

创建表单中的学院、专业、行政班继续使用参考数据级联。密码输入只保存在表单生命周期内；提交后清空字符数组和控件。成功操作刷新当前页并尽量保留选中项；新建账号成功后清除筛选并定位新账号所在结果，若现有接口无法直接返回所在页，则至少刷新第一页并在页顶显示新账号标识，避免用户误以为创建失败。

停用和密码重置使用明确确认步骤。页面不提供删除、基础身份转换或超级管理员相关操作。

### 5.4 教师本人信息

页面顶部身份卡展示姓名、教师工号和职称。下方使用“任职信息”和“联系方式”两张卡片：任职信息包含教师工号、学院和职称，联系方式包含电话和邮箱。

只有联系方式卡可编辑。编辑对话框使用现有服务端校验规则，保存成功后重新获取本人教师资料并更新卡片。页面不提供教师档案管理或角色修改入口。

## 6. 客户端结构

新代码放在 `com.vcampus.client.fx.identity`，按领域分离数据、网络和界面职责：

- `StudentGateway`、`AccountGateway`、`TeacherGateway`：定义阻塞式业务调用边界；
- `SocketStudentGateway`、`SocketAccountGateway`、`SocketTeacherGateway`：适配现有 `VCampusClient` 方法和会话令牌；
- `StudentData`、`AccountData`、`TeacherData`：把 `ResponseMessage` 解析为类型明确、不可变的记录；
- `StudentProfileController`、`StudentAdminController`、`AccountAdminController`、`TeacherProfileController`：负责异步请求、页面状态、权限动作和刷新策略；
- 对应四个 `View`：只负责 JavaFX 控件、布局、用户输入和状态渲染；
- `IdentityUi` 与 `identity.css`：承载共享资料行、状态徽标、空状态和样式。

控制器通过构造函数接收网关、角色集合、执行器和返回工作台回调，测试可注入内存网关。视图不直接调用 `VCampusClient`，也不解析协议键值。

## 7. 路由与生命周期

`CampusApplication` 为四个页面惰性创建控制器：

- `personal-profile` 根据基础身份进入 `StudentProfileController` 或 `TeacherProfileController`；
- `student-status` 进入 `StudentAdminController`；
- `accounts` 进入 `AccountAdminController`；
- `NotificationTarget.STUDENT_PROFILE` 通过 JavaFX 路由进入学生本人学籍。

进入原生页面前，门户沿用现有模块的 `deactivate()` 约定，停止不再需要的临时请求；重新进入时复用控制器并按页面需要刷新。退出登录和应用关闭时调用各控制器 `close()`，取消未完成任务并释放模块执行器。`LegacyModuleBridge` 继续处理尚未迁移的兼容路由，但不再承接上述四条 JavaFX 门户路由。

## 8. 异步、并发与反馈

所有 Socket 调用由模块后台执行器执行，界面状态通过 `Platform.runLater` 更新。每个可重复查询保存请求代次或等价取消令牌：新查询开始后，旧查询即使较晚返回也不能覆盖新结果。离开页面或退出登录后返回的结果必须被忽略。

查询期间禁用重复提交并显示加载状态；编辑或状态变更期间只禁用相关表单动作，不锁死返回导航。网络超时、连接失败、服务端拒绝和解析异常显示可理解的中文信息。列表查询失败保留已有数据并提供重试，保存失败保留用户输入以便修正。

## 9. 数据与安全

本次复用现有 `account.*`、`student.*` 和教师资料动作，不修改 `MessageCodec` 或协议格式。客户端不连接 MySQL，也不缓存密码、令牌以外的敏感凭据到磁盘。

表单沿用现有规则校验必填项、学号或工号格式、日期、邮箱、电话、合法角色组合和密码确认。客户端校验用于即时反馈，服务端结果始终是最终依据。权限不足时显示统一无权限页面，不构造或发送越权请求。

## 10. 测试与验收

自动化测试覆盖：

- 三类响应解析器的正常、空值和非法数据；
- 各网关向现有 `VCampusClient` 传递正确参数；
- 不同角色能看到正确入口和动作；
- 学籍筛选、分页、选中详情及保存后刷新；
- 账号创建、角色合法性、启停和密码重置；
- 本人联系方式编辑和状态历史；
- 快速连续查询时旧响应不会覆盖新响应；
- 学籍消息深链进入新的本人学籍页面；
- 退出登录后控制器不会再更新旧界面。

视觉检查生成 1000、1220、1440 三种内容宽度的关键页面截图，重点检查表格可读性、详情栏、表单、长文本、空状态和错误状态。完成后运行根目录 `mvn clean verify`。

验收标准：

1. JavaFX 门户中的四个目标入口均显示原生 JavaFX 页面，不再显示对应 Swing 面板。
2. 四个页面的业务能力和权限不低于现有实现。
3. 管理页面在常用宽度下能同时完成查询、选中和操作，不出现按钮遮挡或内容拥挤。
4. 本人资料页信息层级清楚，联系方式可编辑，状态与历史易于识别。
5. 创建或修改成功后页面立即显示最新数据，失败时保留输入并说明原因。
6. 学籍消息深链、返回工作台、模块重进和退出登录生命周期正确。
7. 文档、自动化测试和 Maven 全量验证通过。
