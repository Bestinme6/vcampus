# 商店共用收货地址设计

- 日期：2026-09-16
- 状态：交互方案已确认，等待书面规格复核
- 范围：校园商店与二手市场共用地址簿、结算选址、订单地址快照及履约查看权限

## 1. 目标与边界

已登录用户可在商店管理最多三条收货地址。购买普通商品或二手物品时必须选用本人已保存的地址，或填写本次使用的新地址。新地址可只用于当前订单，也可保存；地址簿已满时，用户必须明确选择覆盖哪一条，系统不自动覆盖。

本功能不接入地图、地址自动补全、快递公司、物流单号、外部个人资料或默认地址。地址由用户自行填写，仅用于订单履约，不出现在商品、评价、通知正文或公开用户资料中。二手市场仍按“卖家标记交付、买家确认收货”流转，不因地址功能增加自动放款。

## 2. 用户流程

1. 商店增加“收货地址”入口，可查看、添加、修改、删除本人的地址；两种商店共用这三条记录。
2. 普通商店的购物车结算与立即购买、二手市场的单件购买均进入同一种地址选择体验。未选地址不能确认支付。
3. 选择已保存地址时，结算页展示收件人、电话和完整地址。也可填写新地址，并决定“仅本次使用”或“保存到地址簿”。
4. 保存新地址是独立操作，成功后再用保存的地址结算；即使后续支付失败，用户主动保存的地址仍保留。若已有三条，保存前必须选择具体覆盖哪一条并确认；覆盖不影响历史订单。
5. 确认支付后，订单详情展示下单时的地址快照。修改、覆盖或删除地址簿记录不会改变历史订单。订单地址不支持支付后直接编辑，以免买卖双方看到不同的履约信息。

## 3. 数据与接口

新增共享 `shop_shipping_addresses` 表，以 `(user_id, slot)` 为主键，`slot` 限定为 1～3。这使每个用户在数据库层最多只有三条记录。每条保存收件人姓名、联系电话、完整地址、每次保存都重新生成的版本令牌，以及创建与更新时间；不保存真实示例数据。创建时由服务端选择空槽，满额时必须提供本人的现有槽位作为明确覆盖目标。保存、覆盖和删除需在事务中按用户锁定，防止并发创建超过上限；覆盖、删除均只允许操作当前会话用户的记录。

普通 `shop_orders` 增加收件人、联系电话、完整地址快照字段；新的二手订单从创建时即含相同快照。普通商店旧订单保持快照为空，在详情中明确显示“历史订单无收货地址”，不推断或回填现有地址簿。新订单必须有完整地址快照，不能只保存指向可变地址簿的外键。

新增 `shop.address.list`、`shop.address.save`、`shop.address.delete` 等共享动作；普通和二手结算动作接收两种互斥选择：本人地址槽位与版本令牌，或一次性新地址字段。服务端根据会话解析槽位，在同一结算事务内核对版本令牌、校验地址并生成快照；若地址在预览后被修改、删除或同槽位重建，拒绝付款并提示重新确认。一次性新地址不写入地址簿。购买业务编号的重试先查找已完成订单并返回原订单及原快照，不因地址簿后来变化而再次扣款或改址。

姓名、电话、完整地址由服务端做空值、长度和控制字符校验，客户端只提供即时提示；不以某一地区的手机号格式限制校园用户。具体字段长度以姓名 1～40、电话 5～32、完整地址 5～255 个字符为界。协议使用现有 `MessageCodec`，不允许客户端指定地址所有者或订单买家 ID。

## 4. 查看权限与隐私

- 地址簿仅本人可读取、修改、覆盖或删除；商店管理员和二手卖家也不能浏览他人的地址簿。
- 普通商店订单的地址快照仅订单买家及有履约权限的商店管理员/超级管理员可在订单详情查看。
- 二手订单支付成功后，仅订单买家、该订单卖家，以及处理该订单的商店管理员/超级管理员可在订单详情查看完整收件人、电话和地址；其他卖家及普通用户不能查看。列表和通知不含完整地址。
- 订单快照随历史订单保留，地址簿删除不抹去履约记录；服务端日志、异常消息和审计摘要不记录完整地址或电话。

## 5. 分层与实施顺序

- `vcampus-common`：共享地址字段/协议动作；不在客户端持有数据库凭据。
- `vcampus-server`：地址服务与仓储负责三槽上限、归属、校验和并发；普通/二手结算仓储在同一 JDBC 事务内解析地址、生成快照并创建订单；订单查询按买家、普通商店管理员或特定二手卖家过滤快照。
- `vcampus-client`：原生 JavaFX 商店增加地址管理和可复用的结算选址组件；Socket 请求在后台执行，界面更新回到 JavaFX 应用线程。旧 Swing 商店兼容入口也需提供最小的选址/填写界面，避免服务端强制地址后无法购买；旧入口不扩展完整二手市场。
- 先实现共用地址簿及普通商店结算/订单快照，再让二手市场复用该能力；实施时同步更新数据库迁移、`database/schema.sql`、`docs/shop.md` 和 `docs/requirements.md`。

## 6. 验收

覆盖 0～3 条地址、满额明确覆盖、并发新增、越权槽位、一次性地址不落库、保存后支付失败、预览后地址变化、历史订单快照不变、旧订单无地址展示、两种商店的结算必填，以及二手卖家只可查看自己已付款订单地址。根项目最终运行 `mvn clean verify`。
