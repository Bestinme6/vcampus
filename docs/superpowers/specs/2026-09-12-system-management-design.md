# VCampus 系统管理与审计查询设计

日期：2026-09-12

## 1. 目标

为超级管理员增加独立的“系统管理”模块，补齐需求中已经声明但尚无界面和协议支撑的系统配置管理能力，并提供对现有统一审计日志的只读查询入口。

本次设计只覆盖两类能力：

- 编辑已有学期的业务时间和状态，以及维护全校统一的第 1—12 节作息时间；
- 分页查询 `audit_logs` 中的审计记录。

系统管理沿用现有三层结构：JavaFX 客户端通过 `MessageCodec` Socket 协议访问应用服务器，只有服务端可以访问 MySQL。

## 2. 范围边界

### 2.1 本次实现

- 超级管理员侧栏新增“系统管理”入口；
- 编辑已有学期，不创建、删除学期，也不修改学年和学期序号；
- 维护第 1—12 节课程的可选开始、结束时间；
- 在课表和“我的校园”中按需显示已配置的作息时间；
- 查询统一审计日志，支持组合筛选和分页；
- 学期配置和作息配置变更写入审计日志；
- 更新数据库脚本、迁移、自动化测试和交付文档。

### 2.2 不在本次范围

- 创建或删除学期；
- 修改数据库地址、密码、Socket 端口、线程数或附件目录；这些配置继续由环境变量提供；
- 修改或删除审计记录；
- 把银行流水、商店库存流水或论坛审核日志复制到 `audit_logs`；
- 在线课堂、考试安排和试卷管理；
- 通用、任意键值的系统参数编辑器。

## 3. 方案选择

采用独立 `system.*` 业务域，而不是把功能放进教务模块或建立无类型的通用键值配置表。

独立模块可以让超级管理员权限、协议和页面边界保持清晰。学期仍使用现有 `academic_terms` 表，避免产生两套相互冲突的学期数据；作息时间使用结构化表并进行强类型校验，避免任意字符串配置带来的歧义。

## 4. 权限模型

所有 `system.*` 请求都必须包含有效会话，并且会话角色集合必须严格等于 `{SUPER_ADMIN}`。客户端隐藏入口只用于体验，不能代替服务端校验。

首次登录必须改密的账号不能绕过现有 `ForcedPasswordAccessPolicy` 访问系统管理。审计查询是只读操作；基础配置更新属于关键操作，成功后写入 `audit_logs`。

## 5. 数据模型

### 5.1 学期配置

复用现有 `academic_terms`：

- 不允许修改 `academic_year` 和 `term_number`；
- 可修改 `term_name`、`start_date`、`end_date`；
- 可修改 `selection_start`、`selection_end`、`drop_deadline`；
- 可修改 `status`，仍限定为 `PLANNED`、`SELECTION`、`IN_PROGRESS`、`FINISHED`。

服务端校验：

- 学期开始日期不能晚于结束日期；
- 选课开始时间不能晚于选课结束时间；
- 选课结束时间不能晚于退课截止时间；
- 学期必须存在，更新使用参数化 SQL；
- 不自动改变其他学期状态，避免隐式修改业务数据。

当前 `seed.sql` 对已有学期执行字段覆盖。实现时应改为仅在自然键缺失时插入，避免服务端重启覆盖管理员已经保存的配置。

### 5.2 作息时间

新增 `class_period_times` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `period_number` | `TINYINT` 主键 | 1—12 |
| `start_time` | `TIME NULL` | 本节开始时间 |
| `end_time` | `TIME NULL` | 本节结束时间 |
| `updated_by_user_id` | `BIGINT NULL` | 最后修改人 |
| `updated_at` | `TIMESTAMP` | 最后修改时间 |

初始化时幂等创建 1—12 共十二行，开始、结束时间均为空，不编造学校作息。

校验规则：

- 同一节的开始和结束时间必须同时为空或同时填写；
- 开始时间必须早于结束时间；
- 已配置节次按节次编号比较，后一节开始时间不能早于前一已配置节次的结束时间；
- 一次提交包含完整十二节快照，并在单个数据库事务中更新；
- 服务端从会话取得修改人，忽略客户端提供的操作者信息。

### 5.3 审计查询模型

查询 `audit_logs`，左连接 `users` 取得用户名和显示名。返回字段：

- 审计编号；
- 操作人用户编号，可为空；
- 用户名和显示名，可为空；
- 操作代码；
- 结果代码；
- 客户端地址；
- 创建时间。

筛选条件：用户关键字、操作代码前缀、结果代码、开始日期、结束日期和页码。默认每页 20 条，按 `created_at DESC, id DESC` 排序。所有筛选均使用参数化 SQL；结束日期按次日零点排除边界处理，避免漏掉当天记录。

## 6. 协议与服务端

在 `vcampus-common` 的 `Actions` 中增加：

- `system.config.get`
- `system.config.updateTerm`
- `system.config.updatePeriods`
- `system.audit.search`

共享模块增加系统配置状态、作息时间和审计记录所需的枚举或不可变模型；批量行继续使用 `RowCodec`，不引入 Java 原生对象序列化。

服务端新增：

- `SystemManagementStore`：读取和更新学期、作息时间；
- `SystemManagementRepository`：JDBC 实现，其中作息批量更新使用事务；
- `AuditQueryStore` 与 JDBC 查询实现；
- `SystemManagementService`：会话、权限、输入校验、响应组装和配置变更审计；
- `RequestRouter` 的四个 `system.*` 路由；
- `VCampusServer` 中的依赖装配。

数据库异常对客户端返回可读的通用错误，不暴露 SQL、表名、连接信息或堆栈。配置更新只有数据库提交成功后才返回成功；审计写入沿用当前尽力而为的 `AuditStore` 行为，不让审计存储异常把已经提交的业务配置伪装成失败。

## 7. 客户端

### 7.1 导航与生命周期

超级管理员侧栏在“账号管理”附近新增“系统管理”。路由名使用 `system-management`。页面实例复用现有单窗口内容区，并实现激活、停用和关闭时的异步请求失效处理。

其他角色不显示入口；即使手工构造路由，也跳转到无权限页面。最终权限仍以服务端为准。

### 7.2 基础配置页

页面包含两个区域：

- 学期配置：选择已有学期，查看不可编辑的学年和学期序号，编辑名称、日期、选退课时间和状态；
- 作息配置：以 12 行表单维护每节的开始和结束时间，支持整页保存。

保存按钮在请求期间禁用；成功后刷新当前数据并显示明确反馈；失败时保留用户输入，便于修正后重试。

### 7.3 审计日志页

页面提供用户关键字、操作前缀、结果和日期范围筛选，以及查询、重置、上一页、下一页。表格展示时间、用户、操作、结果和客户端地址；选择一行可查看完整字段。

页面不提供新增、编辑、删除或导出功能。较窄内容区允许横向表格滚动，不截断操作代码。

### 7.4 课表时间展示

系统配置响应提供作息时间。现有课表和“我的校园”在对应节次都已配置时，将节次文字增强为“第 1—2 节 08:00—09:35”；任一端点未配置时只显示“第 1—2 节”。

显示逻辑放在客户端共享格式化组件中，避免 JavaFX 和 Swing 分别实现不同规则。作息查询失败不能阻止课表加载，只降级为仅显示节次。

## 8. 并发与错误处理

- JavaFX 网络请求全部在工作线程执行，视图更新回到 JavaFX Application Thread；
- 页面使用请求代次或现有 `RequestGate` 模式，较晚返回的旧查询不能覆盖当前筛选；
- 两个管理员同时编辑时采用后提交覆盖，界面在保存后重新读取并展示最终值；本次不增加版本号或乐观锁；
- 作息批量更新要么全部成功，要么全部回滚；
- 日期、时间、页码和文本长度在客户端做即时校验，在服务端再次校验；
- 会话失效、无权限、记录不存在和数据库不可用使用不同的可读提示。

## 9. 测试策略

### 9.1 公共模块

- 新增协议动作值和前缀测试；
- 作息时间值对象及格式化边界测试；
- 审计行编解码兼容测试。

### 9.2 服务端

- 只有严格的超级管理员角色集合可以查询和更新；
- 普通用户、业务管理员、过期会话和首次改密会话被拒绝；
- 学期日期和状态校验；
- 十二节完整快照、空值配对、时间顺序及重叠校验；
- 作息事务回滚；
- 审计组合筛选、排序、分页和空用户显示；
- 配置更新成功写入准确动作代码；
- `RequestRouter` 路由和未装配保护；
- `schema.sql`、`seed.sql` 和迁移脚本保持幂等，已有学期配置不会被种子覆盖。

### 9.3 客户端

- 系统管理入口只对超级管理员显示；
- 路由权限与页面生命周期；
- 协议数据解析和畸形响应处理；
- 学期表单和作息表单校验；
- 审计筛选、分页和旧请求失效；
- 配置时间存在与缺失时的课表文本格式化。

最后执行根项目 `mvn clean verify`，并确认普通验证不会产生新的受版本控制截图差异。

## 11. 验收标准

- 超级管理员能够打开系统管理，其他角色在客户端和服务端均无法访问；
- 可以更新已有学期的允许字段，重启服务端后配置不被种子覆盖；
- 可以原子保存十二节作息时间，非法或重叠时间被拒绝；
- 已配置时间出现在课表相关节次文本中，未配置时不显示虚构时间；
- 可以组合筛选并分页查看审计日志，不能修改或删除日志；
- 两类配置变更写入审计日志；
- 数据库结构、代码、协议、测试和文档来自同一变更；
- `mvn clean verify` 通过，且不引入新的工作区污染。
