# VCampus 超级管理员账号管理设计

## 1. 目标与范围

为 VCampus 新增仅超级管理员可见、可用的“账号管理”功能。超级管理员可以创建学生或教师账号、查询账号、修改附加管理员角色、启用或停用账号以及重置密码。

本阶段同时补齐首次登录及密码重置后的强制修改密码流程。系统不提供账号物理删除，不允许通过账号管理创建或授权新的超级管理员。

账号创建统一收归账号管理。学籍管理移除“新增学生”入口及 `student.create` 动作，只保留已有学生档案的查询、编辑、联系方式维护和学籍状态管理。

## 2. 权限与身份规则

- 每个普通账号必须且只能拥有 `STUDENT` 或 `TEACHER` 中的一种基础身份；
- 学生只能附加 `LIBRARY_ADMIN`、`FORUM_ADMIN`；
- 教师可以附加 `STUDENT_ADMIN`、`ACADEMIC_ADMIN`、`LIBRARY_ADMIN`、`SHOP_ADMIN`、`BANK_ADMIN`、`FORUM_ADMIN` 中的任意组合；
- 账号管理的全部动作只允许基础身份为 `SUPER_ADMIN` 的有效会话调用；
- 账号管理不能创建、显示、停用、重置或修改超级管理员账号；
- 基础身份创建后不可修改，附加管理员角色可以修改；
- 学号、教师工号及对应登录名创建后不可修改；
- 客户端隐藏入口只用于改善体验，服务端必须对每次请求重新授权。

## 3. 客户端设计

### 3.1 导航

超级管理员左侧导航在“工作台”正下方显示“账号管理”。学生、教师及各业务管理员均不显示该入口。

点击后在 `MainFrame` 的主内容区切换到账号管理页面，不创建第二个主窗口。工作台和账号管理导航按钮应显示当前选中状态。

### 3.2 账号列表

页面采用现有白色主题，包括：

- 关键词输入框：匹配登录名、学号/工号或姓名；
- 基础身份筛选：全部、学生、教师；
- 状态筛选：全部、启用、停用；
- “查询”按钮；
- 分页表格：账号、姓名、基础身份、管理员角色、启用状态、是否需要改密、最后登录时间；
- 操作按钮：创建账号、修改角色、启用/停用、重置密码、刷新、上一页、下一页。

表格不显示超级管理员，不提供删除按钮。查询和刷新按钮沿用深色粗体高对比样式。网络请求放在后台线程，Swing 组件只在事件分发线程更新。

### 3.3 创建账号

创建对话框先选择学生或教师，再动态显示身份对应字段。

学生字段：

- 学号：10 位数字，同时作为不可编辑的登录名；
- 姓名、性别、出生日期；
- 学院、专业、行政班、入学年份；
- 电话、邮箱、地址；
- 临时密码与确认密码；
- 可选附加角色：图书管理员、论坛管理员。

教师字段：

- 教师工号：`T` 加 7 位数字，同时作为不可编辑的登录名；
- 姓名、学院、职称；
- 电话、邮箱；
- 临时密码与确认密码；
- 可选附加角色：学籍、教务、图书、商店、银行、论坛管理员。

界面不提供超级管理员身份。角色勾选区根据基础身份显示合法选项，服务端仍执行最终组合校验。临时密码为 8—128 位，不在日志或响应中回传。

### 3.4 账号维护

- 修改角色：只修改附加管理员角色，基础身份只读；
- 启用/停用：对目标状态进行二次确认，停用后账号不能登录；
- 重置密码：超级管理员输入并确认新临时密码，系统不显示用户原密码；
- 所有成功提示框使用“操作成功”标题；
- 未选择表格记录、字段格式错误、网络失败和服务端拒绝均显示明确中文提示。

## 4. 强制修改密码

账号创建和密码重置均将 `users.force_password_change` 设置为 `TRUE`。

登录成功后，客户端读取响应中的 `forcePasswordChange`：

1. 如果为 `false`，正常进入工作台；
2. 如果为 `true`，只打开强制修改密码窗口；
3. 用户输入当前临时密码、新密码和确认密码；
4. 修改成功后，服务端更新密码哈希和随机盐，将标志设为 `FALSE`，更新当前会话状态；
5. 客户端随后进入工作台；
6. 用户取消窗口时发送退出请求并返回登录界面。

服务端在统一请求路由层限制强制改密会话：除 `auth.changePassword`、`auth.logout` 和 `auth.session` 外，所有业务动作均返回“请先修改初始密码”。新密码必须为 8—128 位且不能与当前密码相同。

## 5. 公共协议

在 `vcampus-common` 增加以下动作：

| Action | 用途 |
| --- | --- |
| `account.search` | 分页查询学生和教师账号 |
| `account.referenceData` | 查询学院、专业、班级及合法角色选项 |
| `account.create` | 事务创建学生或教师账号及档案 |
| `account.updateRoles` | 修改目标账号的附加管理员角色 |
| `account.setEnabled` | 启用或停用目标账号 |
| `account.resetPassword` | 设置临时密码并要求下次登录修改 |
| `auth.changePassword` | 当前用户验证旧密码并修改自己的密码 |

分页表格继续使用现有 `RowCodec` 编码，角色集合使用逗号分隔的枚举名称传输。协议只传必要字段，不传密码哈希、盐或其他敏感数据库字段。

## 6. 服务端结构

### 6.1 组件

- `AccountService`：会话授权、参数校验、身份及角色组合校验、密码哈希、异常转换和审计；
- `AccountRepository`：账号搜索以及账号、角色、学生/教师档案的事务写入；
- `AuthService`：新增当前用户修改密码流程；
- `SessionManager`：新增按用户撤销全部会话及更新当前会话强制改密状态的能力；
- `RequestRouter`：新增 `account.*` 路由，并统一阻止强制改密会话访问业务动作。

### 6.2 创建事务

学生创建事务依次写入：

1. `users`，登录名等于学号；
2. `user_roles`，包含 `STUDENT` 和选中的合法附加角色；
3. `student_profiles`；
4. `student_status_history`，初始状态为“在读”，变更人为当前超级管理员。

教师创建事务依次写入：

1. `users`，登录名等于教师工号；
2. `user_roles`，包含 `TEACHER` 和选中的合法附加角色；
3. `teacher_profiles`。

任一步失败均回滚整个事务。数据库使用当前不区分大小写的唯一排序规则阻止大小写变体重复账号，登录仍使用现有 `BINARY` 精确匹配保持大小写敏感。

### 6.3 维护事务与会话

- 修改角色在一个事务中保留基础身份、替换附加角色，并再次执行 `RoleCompositionPolicy`；
- 停用账号、修改角色或重置密码成功后，撤销目标用户的全部现有会话；
- 启用账号不自动建立会话；
- 重置密码写入新的 PBKDF2 哈希和随机盐，并设置 `force_password_change=TRUE`；
- 用户自行修改密码时验证当前密码，写入新哈希和盐，设置 `force_password_change=FALSE`，只保留并更新发起改密的当前会话；
- 重复提交目标当前状态时返回成功但不产生错误数据。

## 7. 数据与审计

现有 `users`、`user_roles`、`student_profiles`、`teacher_profiles` 和 `student_status_history` 已能支持本功能。本阶段不新增业务表；课程演示数据量较小，也不新增专用查询索引。

以下操作写入 `audit_logs`：

- `account.create`；
- `account.updateRoles`；
- `account.setEnabled`；
- `account.resetPassword`；
- `auth.changePassword`。

审计记录只保存操作人、动作、结果和时间，不记录明文密码、哈希、盐或完整请求参数。

## 8. 错误处理

- 非超级管理员调用账号管理：返回“无权执行此操作”；
- 强制改密会话访问业务接口：返回“请先修改初始密码”；
- 登录名、学号或工号重复：返回对应字段已存在；
- 身份或角色组合非法：返回明确角色规则提示；
- 学院、专业、班级关联不一致：拒绝创建；
- 密码格式错误或两次输入不一致：客户端先提示，服务端再次校验；
- 数据库异常：事务回滚，对客户端返回通用数据库错误，服务端控制台只记录不含敏感数据的诊断信息；
- 网络请求失败：客户端恢复按钮状态并显示可读错误。

## 9. 测试与验收

自动化测试覆盖：

- 超级管理员授权以及学生、教师和业务管理员拒绝；
- 学生与教师合法和非法角色组合；
- 学生、教师创建事务的完整写入与失败回滚；
- 重复登录名、学号和工号；
- 查询筛选、分页和超级管理员排除；
- 修改角色、启停、重置密码后的会话撤销；
- 临时密码强制修改、旧密码失效、新密码生效；
- 强制改密会话无法访问业务接口；
- 账号管理导航仅超级管理员可见；
- 创建表单依据身份显示正确字段和角色；
- 移除学籍管理“新增学生”后，原有查询、编辑、状态及教务流程保持可用。

完成后执行根目录 `mvn clean verify`。本机验收时重新执行最新 `database/schema.sql`，重启服务端和客户端，用超级管理员分别创建一个学生和教师账号，验证角色工作台、首次改密、停用、角色修改和密码重置流程。

## 10. 明确不在本阶段实现

- 创建、修改或删除超级管理员；
- 物理删除学生或教师账号；
- 修改基础身份、学号、教师工号或登录名；
- 批量导入账号；
- 用户自行找回忘记的密码；
- 学生和教师自行修改姓名、学院、专业、班级或职称。
