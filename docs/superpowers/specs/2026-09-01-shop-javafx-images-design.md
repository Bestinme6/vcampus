# 商店 JavaFX、商品图片与购买流程升级设计

日期：2026-09-01
状态：用户已确认，待编写实施计划

## 1. 目标与边界

本轮把现有 Swing 表格式校园商店升级为原生 JavaFX 商城界面，增加商品图片、商品详情、立即购买确认和更直观的购物车，同时保留现有订单、库存、虚拟银行支付、取消退款、发货、确认收货和消息通知能力。

继续遵守 MySQL → 应用服务器 → JavaFX 客户端三层 C/S 架构。客户端不得连接 MySQL，也不得读取服务端图片真实路径。共享动作与分类放在 `vcampus-common`，图片存储、JDBC、权限和事务放在 `vcampus-server`，页面、缓存和客户端网络适配放在 `vcampus-client`。网络仍使用 `MessageCodec` 长度限制二进制协议，不使用 Java 原生对象序列化。

本轮不接入真实支付渠道、外部图床、多商户、优惠券、物流接口、商品评价、促销推荐系统或独立商品分类管理后台。固定分类为：学习文具、生活用品、数码配件、校园周边、其他。

## 2. 已确认视觉方向

商店采用清爽的校园门户卡片风格，而不是复制淘宝或京东的高密度布局。使用独立 `shop.css`，沿用现有 JavaFX 校园门户的蓝白色体系、字体和 Feather 图标，不改变其他模块样式。

商品首页包含商店标题、搜索、购物车数量、简洁宣传区、固定分类、排序和响应式商品卡片。卡片展示封面、商品名、价格与必要库存状态，整张卡可进入详情。宽内容区显示四列，并根据可用宽度缩为三列或两列；页面不产生横向滚动。

购买者页面不使用表格。管理员商品和订单列表可使用 JavaFX `TableView` 保持管理效率，但商品新建和编辑进入独立可视化表单。

浏览器视觉草图仅用于确认结构。最终验收必须渲染实际 JavaFX 页面截图，不能把草图当作产品实现。

## 3. 页面与路由

JavaFX 商店使用单窗口内部路由：

```text
商品首页 → 商品详情 → 立即购买确认 → 订单详情
    │          └→ 加入购物车
    ├→ 购物车 → 购物车结算确认 → 订单详情
    └→ 我的订单 → 订单详情

管理员入口 → 商品管理 → 新建/编辑商品
          └→ 订单管理 → 订单详情
```

### 3.1 商品首页

- 按货号或商品名搜索，按固定分类筛选，支持明确的价格和默认排序；筛选与分页由服务端执行。
- 列表响应先返回商品文字数据与封面图片元数据，不在一条商品行内嵌入完整图片。
- 卡片先显示主题占位图，再异步加载封面缩略图。单张图片失败不影响商品列表其余内容。
- 没有商品、没有匹配结果、网络失败和重试分别显示明确状态。

### 3.2 商品详情与立即购买

- 详情显示最多五张图片、名称、货号、分类、说明、当前价格、库存和购买数量。
- 第一张排序图片为封面；缩略图选择切换主图。没有图片时使用统一客户端占位图。
- “加入购物车”成功后停留在详情页，并刷新商店内购物车数量。
- “立即购买”跳过购物车，进入独立订单确认页，不直接扣款，也不修改原购物车。
- 确认页展示商品、数量、预估总额和账户余额。用户点击“确认支付”后才发起服务端结算。
- 服务端发现价格或库存变化时不沿用过期确认结果；客户端刷新真实数据并要求用户重新确认。

### 3.3 购物车与订单

- 购物车以商品卡片列表加固定金额汇总呈现，支持勾选部分商品、修改数量和移除。
- 下架、缺货或数量超过库存的商品仍显示，并说明不可购买原因，但不能勾选结算。
- 购物车结算进入与立即购买一致的订单确认体验。成功后只删除本次已购买项，未勾选项保持不变。
- 订单页面保留已有支付、取消退款、发货和确认收货状态规则。
- 订单项继续保存货号、名称、单价、数量和小计快照。商品图片不复制到订单项；历史订单优先显示当前商品封面，图片不可用时显示占位图，不影响订单凭证。

### 3.4 管理员商品编辑

- 商品管理列表支持查询、上下架、新建和进入编辑；库存调整继续走独立带原因操作。
- 编辑页包含名称、固定分类、说明、价格、上下架状态和图片区。货号继续由服务端生成且编辑时不可修改。
- 每件商品最多五张图片，可上传、预览、删除、拖动排序和设置封面。
- 新建商品先保存基础信息取得服务端商品 ID，再上传图片。编辑时图片变更使用暂存状态；点击保存后统一提交，取消则丢弃暂存变更。
- 商品基础信息或图片提交失败时，原商品和原图片保持可用，不展示半完成状态。

## 4. 图片存储与数据库

采用服务端文件存储加 MySQL 元数据。图片根目录由 `VCAMPUS_SHOP_IMAGE_DIR` 配置；未配置时使用服务端配置定义的安全默认数据目录，不写死开发者机器路径。客户端只持有图片 ID、哈希和显示元数据。

新增 `shop_product_images` 表，至少包含：

- `id BIGINT` 主键；
- `product_id BIGINT NOT NULL`，关联商品；
- `storage_key VARCHAR(...) NOT NULL UNIQUE`，服务端生成的不可猜测存储键；
- `thumbnail_storage_key VARCHAR(...) NOT NULL UNIQUE`；
- `mime_type VARCHAR(...) NOT NULL`；
- `byte_size BIGINT NOT NULL`；
- `sha256 CHAR(64) NOT NULL`；
- `sort_order INT NOT NULL`；
- `is_cover BOOLEAN NOT NULL`；
- `created_at`、`updated_at`。

为同一商品的显示顺序设置唯一约束。每件商品最多一张封面，由事务内校验和数据库可表达的约束共同保证。没有图片时不写占位记录。`shop_products` 增加固定分类字段，已有商品迁移为“其他”。

同步更新 `database/schema.sql`，新增 `database/migrations/013_shop_images_javafx.sql`。`database/seed.sql` 为演示商品补充分类，但不写入绝对图片路径，不覆盖管理员已有分类或图片数据。

## 5. 图片上传、处理与读取

正式支持 JPG 和 PNG；单张不超过 2 MB，每件商品最多五张。暂不支持 WebP，避免额外引入 JavaFX 21 默认不具备的图片解码依赖。

上传流程：

1. 管理员发起上传，服务端创建绑定当前会话、管理员和目标商品的短期上传 ID。
2. 客户端按序发送 Base64 分块。每块约对应 192 KB 原始数据，使编码后仍明显低于 `MessageCodec` 单字符串 1 MB 上限。
3. 服务端限制总大小、块数、顺序、重复块和有效时间，并只向该上传会话的拥有者开放续传。
4. 接收完成后检查真实文件头、MIME、可解码性、像素上限和哈希；随后重新编码或规范化，并生成列表缩略图。
5. 文件先进入图片根目录内的临时区。客户端提交一份图片计划，包含按顺序排列的已有图片 ID、新上传 ID、封面选择和删除集合。
6. 服务端在一个提交操作中校验整份计划，转正新文件并在一个数据库事务中替换图片元数据；数据库失败时清理新文件并保留旧数据。提交成功后再清理已删除的旧文件。

客户端原始文件名不参与服务器路径拼接。正式文件名和目录由服务端存储键生成，禁止路径穿越。临时上传到期自动清理，服务启动时补充清理遗留临时文件和超过保留期、数据库未引用的孤立正式文件。

商品列表只下载封面缩略图；详情按需下载原图或适合桌面展示的规范化版本。客户端图片缓存以图片 ID、哈希和规格为键，管理员替换图片后自然失效。缓存文件先写临时文件再原子替换，下载中断不会留下可读半文件。

## 6. 公共协议与服务端边界

`vcampus-common` 新增固定商品分类枚举和动作常量：

- `shop.product.get`；
- `shop.image.getChunk`；
- `shop.buyNow`；
- `shop.admin.image.uploadStart`；
- `shop.admin.image.uploadChunk`；
- `shop.admin.image.uploadComplete`；
- `shop.admin.image.commit`。

动作参数仍使用字符串映射，图片分块使用 Base64。`uploadComplete` 只产生已验证的短期上传记录，不立即改变商品；`image.commit` 一次提交保留、删除、排序和封面计划。协议版本和旧动作字段含义保持兼容；旧客户端不传分类或选择集合时保持原有行为。

`vcampus-server` 新增 `ShopImageStore` 接口和文件系统实现，负责上传会话、文件验证、缩略图、正式存储和清理。`ShopRepository` 继续负责商品、图片元数据、购物车、订单和 JDBC 事务，不直接依赖 JavaFX 或客户端路径。

`shop.buyNow` 和购物车部分结算复用同一个结算事务引擎：会话确定买家，服务端读取并锁定商品，重新计算价格，校验库存和银行账户，完成扣款、银行流水、订单、订单项快照、库存扣减、库存流水和支付通知。立即购买不读写购物车；购物车结算只清理选中的成功结算项。两种流程继续使用唯一结算操作编号保证重试幂等。

## 7. JavaFX 客户端结构

在 `vcampus-client` 新增 `com.vcampus.client.fx.shop` 包，至少拆分为：

- `ShopView`：页面和路由容器；
- `ShopController`：会话级状态、导航、请求代次和业务编排；
- `ShopGateway` / `SocketShopGateway`：协议调用边界；
- `ShopData`：页面需要的不可变数据记录与解码；
- `ShopImageCache`：缩略图、详情图下载和缓存；
- 商品卡、详情、购物车、确认、订单和管理员编辑等聚焦组件；
- 独立 `shop.css`。

所有 Socket、文件和图片处理在后台执行器完成，所有 Scene Graph 更新回到 JavaFX Application Thread。切换页面、注销或关闭时取消可取消任务，使用会话代次和请求代次忽略迟到回调。控制器不能继续堆入 `CampusApplication`。

主导航默认进入新的 JavaFX 商店。旧 `ShopModulePanel` 暂时保留兼容，不复制新增视觉能力；待新商店完成回归后再单独决定是否删除。

## 8. 权限、安全与失败行为

- 所有商品管理和图片动作由 `ShopService` 根据服务端会话检查商店管理员或超级管理员权限。客户端隐藏按钮不构成安全边界。
- 图片上传 ID 绑定会话、管理员和商品；其他用户不能读取、续传或完成该上传。
- SQL 使用参数绑定。客户端不能提交服务端文件路径、买家 ID、任意分类值或订单价格。
- 图片验证覆盖伪造扩展名、伪造 MIME、超大文件、超大像素、乱序和重复分块、过期上传及路径穿越。
- 图片加载失败时显示占位图与重试，不阻塞商品文字内容。
- 上传失败只标记对应暂存图片，其他暂存内容不丢失。
- 保存失败保留原商品和原图片；临时文件由即时补偿或过期任务清理。
- 价格或库存变化刷新确认页并要求再次确认。
- 余额不足、账户冻结、商品下架或库存不足时不创建订单、不扣款、不减库存。
- 网络响应丢失时按结算操作编号返回原订单，不能重复扣款或重复通知。

## 9. 验证与验收

公共模块测试覆盖动作、固定分类、图片分块参数、字段上限和旧协议兼容。

服务端测试覆盖图片格式、大小、像素、哈希、缩略图、乱序或重复分块、上传越权、路径安全、超时与启动清理，以及文件和数据库失败时的补偿。服务与数据库测试覆盖商品详情、分类筛选、立即购买、购物车部分结算、价格变化、库存不足、账户冻结、权限、幂等和现有取消退款/发货流程回归。

客户端测试覆盖 JavaFX 路由、响应式卡片、图片加载与重试、详情图切换、购物车选择、支付确认、上传预览和排序、过期回调抑制、退出清理与 FX 线程归属。

使用测试专用数据渲染商品首页、详情、购物车、订单确认和管理员编辑页实际 JavaFX 截图。覆盖正常、空数据、长商品名、无图片、加载失败、下架和库存不足状态，并检查 1440×900、1280×800 和约 1000 像素宽窗口。功能通过但页面拥挤、裁切、双重滚动或与校园主题不一致，仍不算完成。

最终执行根目录 `mvn clean verify`。真实 MySQL、服务端图片目录权限、多客户端上传、图片下载缓存和并发购买需单独手工验收；未执行的外部环境验证在交付时明确说明。

更新 `docs/requirements.md` 和 `docs/shop.md` 的功能状态与验收说明，不替用户修改本机 MySQL、启动正式服务端或写入真实个人数据。
