# VCampus 消息中心设计

## 1. 目标与范围

为 VCampus 增加所有已登录用户可用的站内消息中心。业务模块在关键外部操作成功时向受影响用户写入通知；客户端在左侧“消息中心”显示未读数字角标，并提供搜索、分类、分页、详情、单条已读和全部已读功能。

首版接入以下事件：

- 教务管理员或超级管理员创建教学班并为教师安排课表；
- 教学班最终成绩发布；
- 学生学籍状态发生真实变更；
- 普通账号的附加管理员角色发生真实变更；
- 普通账号被启用或停用；
- 普通账号密码被超级管理员重置。

账号创建不发送站内消息，因为目标用户尚未使用过该账号。后续图书馆、商店、银行和论坛模块通过相同通知写入接口扩展，不另建消息表。

## 2. 架构选择

采用“业务数据与通知同事务写入”的方案，不使用业务完成后再单独写消息，也不引入事件队列或 Outbox。

排课、成绩发布、学籍状态和账号维护的仓储事务在业务变更成功后、提交前写入通知。通知插入失败时整个事务回滚；业务操作失败时不产生通知。这一设计保证“业务成功必有消息，业务失败绝无消息”，适合当前单体应用服务器和课程演示规模。

服务端提供统一的通知写入组件。各业务仓储只负责提供接收用户、发送用户、消息类型、文案和跳转目标，不自行拼装 SQL。未来模块复用同一组件。

## 3. 数据设计

新增 `notifications` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | 消息主键 |
| `recipient_user_id` | 接收用户，必填 |
| `sender_user_id` | 实际操作用户，可空；删除用户后置空 |
| `notification_type` | 固定消息类型枚举 |
| `source_module` | `ACADEMIC`、`STUDENT_STATUS`、`ACCOUNT_SECURITY` 等来源模块 |
| `title` | 消息标题 |
| `content` | 完整正文，不保存密码等敏感数据 |
| `target` | 固定业务跳转枚举，可空 |
| `related_entity_id` | 关联教学班、学生档案等记录 ID，可空 |
| `is_read` | 是否已读，默认 `FALSE` |
| `read_at` | 首次标记已读时间 |
| `created_at` | 创建时间 |

为 `(recipient_user_id, is_read, created_at)` 建立索引，以支持未读数量和倒序分页。消息不提供物理删除，首版不开发归档、订阅设置和自定义通知偏好。

公共模块新增固定枚举：

- 类型：`SCHEDULE_ASSIGNED`、`GRADE_PUBLISHED`、`STUDENT_STATUS_CHANGED`、`ROLES_CHANGED`、`ACCOUNT_ENABLED`、`ACCOUNT_DISABLED`、`PASSWORD_RESET`；
- 来源：`ACADEMIC`、`STUDENT_STATUS`、`ACCOUNT_SECURITY`；
- 跳转：`TEACHER_SCHEDULE`、`STUDENT_GRADES`、`STUDENT_PROFILE`、`NONE`。

服务端不接受客户端提供任意类名、命令或页面路径。

## 4. 公共协议与权限

新增 `notification.` 动作：

| Action | 说明 |
| --- | --- |
| `notification.search` | 按关键词、来源分类、已读状态和页码查询当前用户消息 |
| `notification.get` | 获取当前用户的一条完整消息 |
| `notification.unreadCount` | 获取当前用户未读总数 |
| `notification.markRead` | 将当前用户的一条消息标记为已读 |
| `notification.markAllRead` | 将当前用户全部未读消息标记为已读 |

所有接口根据会话中的 `userId` 确定接收用户。客户端不能传入目标用户 ID，也不能读取或修改其他用户的消息。不存在或不属于当前用户的消息统一返回“消息不存在”。

列表分页继续使用 `RowCodec`。列表只返回卡片所需摘要；详情接口返回完整正文和跳转目标。首版每页 10 条，按 `created_at DESC, id DESC` 排序。

## 5. 业务通知规则

只有数据发生真实变化时才发送通知。重复角色集合、重复启停状态、相同学籍状态和已经发布的成绩不会生成重复消息。

### 5.1 排课通知

- 时机：新教学班、全部课表时段和相关数据在同一事务中写入后、提交前；
- 接收者：教学班的 `teacher_user_id`；
- 来源：教务处；
- 示例：`教务管理员张老师已为您安排《Java程序设计》教学班，请查看教师课表。`；
- 跳转：教师课表；
- 后续若增加教学班课表编辑，沿用相同类型，并使用“已修改”文案。

### 5.2 成绩发布通知

- 时机：全班成绩完整校验通过，成绩正式发布并将教学班置为完成状态的同一事务中；
- 接收者：该教学班所有状态为 `ENROLLED` 的学生账号；
- 来源：教务处；
- 示例：`任课教师王老师所授《数据库系统原理》的最终成绩已发布，请查看。`；
- 跳转：我的成绩；
- 教师暂存或修改未发布成绩时不通知。

### 5.3 学籍状态通知

- 时机：学生状态与原状态不同，状态和历史记录写入后、提交前；
- 接收者：学生档案关联的用户账号；
- 来源：学籍管理；
- 示例：`学籍管理员李老师已将您的学籍状态由“在读”变更为“休学”。原因：个人申请。`；
- 跳转：学籍信息。

### 5.4 账号安全通知

- 角色变更：列出新增和取消的业务管理员角色；完全相同的角色集合不通知；
- 启停：只有启用状态实际改变时通知。停用消息保留，账号重新启用并登录后仍可查看；
- 密码重置：说明密码已被管理员重置，要求使用临时密码登录并修改；消息不包含临时密码、密码哈希或盐；
- 接收者：目标普通账号；
- 来源：账号安全；
- 跳转：无。

账号维护继续撤销目标用户已有会话。重置后的用户必须先完成强制改密，之后才能访问消息中心。

## 6. 客户端界面

参考用户提供的移动端消息列表图片，保留搜索、未读红点、来源、摘要、时间和“一键已读”，改造为 Swing 桌面布局，不复制手机状态栏、返回栏或底部导航。

### 6.1 主导航角标

- 所有正常登录用户都显示“消息中心”导航；
- 1—99 条显示具体数字，超过 99 条显示 `99+`，0 条隐藏；
- 登录进入主窗口后立即查询一次，此后每 10 秒查询一次；
- 轮询在后台线程执行，同一时刻最多一个未读请求；
- 读取消息、全部已读后立即刷新角标；
- 主窗口关闭、退出登录或会话失效后停止定时器。

### 6.2 消息列表

消息中心在 `MainFrame` 当前内容区显示，不创建第二个主窗口。页面包括：

- 标题“全部消息”；
- 关键词搜索；
- 已读状态筛选；
- 来源分类：全部消息、教务通知、学籍通知、账号安全；
- “一键已读”；
- 10 条一页的消息卡片；
- 上一页、页码、下一页。

卡片显示模块图标、未读红点、来源、标题、正文摘要和时间。未读卡片使用轻微强调背景，已读卡片使用普通白色背景。没有消息时显示“暂无消息”。

### 6.3 消息详情

点击卡片打开模态详情窗口，显示来源、标题、发生时间和完整正文，并在后台标记为已读。根据 `target` 显示“查看教师课表”“查看我的成绩”或“查看学籍信息”按钮；账号安全通知不显示跳转按钮。

跳转只使用公共模块中的固定枚举。目标页面暂时不可用时仍允许阅读消息，并显示可读提示。

## 7. 错误与并发处理

- 业务事务中的通知插入失败：回滚业务数据，返回“操作未完成，请稍后重试”；
- 未读轮询失败：不弹窗、不清零原角标，10 秒后自动重试；
- 搜索、详情和已读操作失败：保留当前页面状态并显示明确错误；
- 单条已读和全部已读使用幂等更新，重复调用返回成功；
- 详情窗口可以先显示已取得的内容；标记已读失败时保留未读状态，用户可再次打开重试；
- 客户端所有网络操作在后台线程执行，Swing 组件只在事件分发线程更新；
- 批量成绩通知使用批处理写入，避免为每个学生单独建立数据库连接。

## 8. 测试与验收

自动化测试覆盖：

- 数据表约束、索引和消息映射；
- 用户只能查询、读取和标记自己的消息；
- 搜索、来源分类、已读筛选、稳定分页和未读数量；
- 单条已读和全部已读的幂等性；
- 六类业务事件的正确接收者、正文和跳转目标；
- 业务失败不生成通知，通知失败使业务事务回滚；
- 相同状态或相同角色不重复通知；
- 成绩发布批量通知全部在选学生，排除退课学生；
- 强制改密会话不能读取消息；
- 角标 0、1—99、99+ 显示规则；
- 10 秒轮询不重叠，退出后停止；
- 消息解析异常返回可读错误。

本机验收步骤：

1. 执行最新 `database/schema.sql` 和对应迁移脚本；
2. 启动服务端和两个客户端；
3. 用超级管理员或教务管理员给教师排课，验证教师在 10 秒内出现角标和排课消息；
4. 发布一个教学班的最终成绩，验证所有在选学生收到消息，退课学生不收到；
5. 修改学生学籍状态，验证学生收到包含旧状态、新状态和原因的消息；
6. 修改角色、启停和重置密码，验证目标账号重新登录后收到账号安全消息；
7. 测试搜索、分类、分页、详情、单条已读和全部已读；
8. 验证普通用户不能通过构造请求查看他人消息。

完成后执行根目录 `mvn clean verify`。

## 9. 首版明确不实现

- 用户之间的私聊或群聊；
- 服务端主动推送和长连接；
- 消息删除、归档和撤回；
- 消息订阅设置与免打扰；
- 邮件、短信或手机系统通知；
- 自定义富文本、附件和任意 URL 跳转；
- 账号创建通知。
