# 数据库自动重建实施计划

用户已批准方案 A 和设计文档；在当前对话串行实施，不使用子智能体。

1. 将 schema/seed 作为 Maven 资源打包；新增元数据表。规范化换行后计算指纹，避免 Windows/Linux 换行触发清空。
2. 实现 SQL 解析、受控表清单、目标库校验、命名锁、失败标记失效和完整重建。忽略规范脚本的 CREATE DATABASE/USE，由经过校验的 JDBC catalog 决定执行目标。
3. 在 ServerMain 和 AdminBootstrapMain 接入。seed 不含默认登录账号，管理员继续通过已有安全工具创建。
4. 用单元测试覆盖解析和目标检查；用独立、随机命名的 MySQL 测试库覆盖全量脚本、旧库重建、二次启动保留数据、失败重试、并发和未知表保护。禁止在日常 vcampus 数据库运行清空测试。
5. 更新 README、需求状态和忽略规则；检查已有商店 SQL 修复；执行根 Maven clean verify。
6. 审查差异与待推送内容，准备提交；GitHub 推送仍留到用户对具体发布结果确认之后。

设计细化：数据库必须已存在；不创建 MySQL 账号。元数据先失效、最后成功提交，失败后下次启动可重试；不宣称 MySQL DDL 可整体回滚。外部表引用 VCampus 表时拒绝重建，以免破坏不属于本项目的数据。相同脚本指纹但缺表时也重建。
